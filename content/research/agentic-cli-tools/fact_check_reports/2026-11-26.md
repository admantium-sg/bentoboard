## 6. Trend analysis

- **Release-telemetry claims age within hours.** Seven of seven dist-tag assertions ("latest = X", "alpha still points at Y", "stable frozen at Z") were correct at window close but stale by the time of the check 30–48 h later. Recommendation for the accumulator: phrase dist-tag claims as **window-close snapshots with a timestamp**, never as present tense.
- **Superlatives are the recurring error class.** "The heaviest release window in this series", "the largest OpenCode release set observed", "the first under the corrected package name", "the longest freeze recorded for this package" — all four were falsified, while the underlying timestamps were exact. Recommendation: superlatives need a stated comparison window or a queryable series, otherwise they should be dropped.
- **Derived numbers are unreliable.** The −2.31 % figure for the ANT bar was internally consistent with a wrong close (86.86); the real close was 87.64 (−1.43 %). Percentages and deltas should be recomputed from the primary bar, not from the note's own text.
- **Primary APIs were sufficient for 15/15 claims.** Zero generic web searches were needed; every check resolved against npm registry JSON, GitHub REST, SEC EDGAR, Yahoo/Nasdaq/stockanalysis or jsDelivr. Third-party aggregators were only needed as a second source, never as the primary.
- **The active knowledge base is drifting out of the retention window.** The `## 2026-11-24` and `## 2026-11-25` sections plus this run's comments push the active file to ~67 KB, above the ~60 KB budget noted in the header. The next accumulator cycle should re-condense, and the fact-check backlog (96 archived claims) should be scheduled explicitly rather than carried forward indefinitely.
