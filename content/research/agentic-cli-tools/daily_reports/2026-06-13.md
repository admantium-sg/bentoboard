## New Findings (June 12)

### Claude Code v2.1.174–175 (June 12, 2026) — Two Releases, GovCloud Fix, Model Picker Overhaul

Claude Code shipped two releases in a single day — a notable cadence:

**v2.1.175 (June 12 evening):**
- **`enforceAvailableModels` managed setting**: When enabled, the `availableModels` allowlist also constrains the Default model — a Default that would resolve to a disallowed model now falls back to the first allowed model, and user/project settings can no longer widen a managed `availableModels` list. Enterprise governance feature.

**v2.1.174 (June 12):**
- **`wheelScrollAccelerationEnabled` setting**: Disable mouse-wheel scroll acceleration in fullscreen mode
- **Model picker fixes**: Fixed `/model` picker hiding the model family that Default resolves to; fixed hardcoded Sonnet version label when `ANTHROPIC_DEFAULT_SONNET_MODEL` pins a different Sonnet; fixed `availableModels` restrictions not being applied to subagent model overrides
- **Bedrock GovCloud fix**: Fixed GovCloud regions (`us-gov-*`) deriving the wrong inference profile prefix (`global` instead of `us-gov`), causing 400 errors on derived model IDs
- **Background session env fix**: Fixed background sessions inheriting another session's `ANTHROPIC_*` provider env from the shell that started the background daemon
- **CPU reduction**: Fixed a 1-2 second pause when exiting shortly after a shell command was interrupted/killed on macOS and Linux; reduced idle CPU during `/goal` status chip rendering
- **Skill hot-reload**: Only changed skills are now re-announced (not the entire skill listing)
- **VSCode usage attribution**: Added per-skill/agent/plugin/MCP breakdown in Account & usage dialog over last 24h or 7d

**Source:** https://code.claude.com/docs/en/changelog

## Community Pulse

### Working Well
- **Kilo's embedded LanceDB**: The switch to embedded LanceDB as default is being well received — eliminates the need for a separate Qdrant vector store for semantic search, which was a friction point for self-hosted deployments. One less infrastructure dependency.
- **Claude Code's GovCloud fix**: Enterprise users on AWS GovCloud regions were getting 400 errors on derived model IDs since the Bedrock support launch. Quick fix after June 10's initial release.
- **Droid's destructive command marking**: Commands that could destroy the working tree being treated as high-risk is seen as a good safety-by-default pattern — mirrors Claude Code's `acceptEdits` hardening.

### Problems
- **Codex CLI v0.140.0 stable still not out**: 16 alphas and counting — the community is expressing mild frustration about the extended alpha cycle. Some asking whether the multi-agent v2 features are causing the delay.
- **Cline's concurrent version tracks**: Still no resolution to the dual-track versioning (v3.0.x stable vs v3.89.x latest) creating confusion about which version to install.

### Interesting
- **Claude Code `enforceAvailableModels`**: This managed setting is a significant enterprise governance feature — organizations with `availableModels` allowlists can now enforce that even the Default model is constrained, preventing users from bypassing model restrictions by falling back to Default. A controlled Default is now possible.
- **Kilo's autonomy preset onboarding**: The ability to choose agent autonomy level during setup suggests Kilo is trying to address the novice-expert spectrum — different users want different levels of agent independence from day one.
- **Crush moving to sigstore verification**: The shift to cosign/sigstore artifact verification for nightly builds suggests Charm is preparing for more formal release signing — important as Crush gains enterprise adoption.

---

## Trend

The ecosystem is in a hardening and governance phase rather than feature expansion. Claude Code is tightening enterprise controls (`enforceAvailableModels`, GovCloud fix, usage attribution), Kilo is simplifying self-hosted deployments (embedded LanceDB) and polishing JetBrains UX, and Droid is improving safety defaults (destructive command marking, context summarization fallback). Meanwhile, Codex CLI's 16-alpha cycle suggests v0.140.0 stable is finalizing multi-agent v2 concurrency — the next major capability unlock. The tools are maturing: feature velocity is down, reliability and governance polish is up.
