## New Developments by Tool

### 1. Cursor ✅ MAJOR NEW RELEASE (Cursor 3.1)

**Latest Release:** Cursor 3.1 (Post-April 13, 2026)

**New Features:**

**Tiled Layout (Agents Window Enhancement):**
- Split view into panes to run and manage multiple agents in parallel
- Expand panes to focus on specific conversations
- Drag agents between tiles
- Keyboard shortcuts for quick navigation and organization
- Layout persists across sessions
- Makes multi-tasking and comparing agent outputs easier without tab switching

**Upgraded Voice Input:**
- More reliable and accurate dictation
- Records full voice clip with batch STT (Speech-to-Text)
- Higher-quality transcription
- Keyboard shortcut: Ctrl+M to speak
- UI improvements: waveform visualization, timer, cancel/confirm buttons
- Better voice input controls while recording

**Branch Selection in Empty State:**
- Previously defaulted to current branch when starting agent
- Now can search and select branch first
- Launch cloud agent directly against chosen branch
- Reduces accidental runs on wrong branch
- Cuts down steps to switch branches

**Diff to File Navigation:**
- Jump from diff directly to exact line in file
- Full editor power after jump (manual edits, Tab completion, go to definition)
- Streamlines review workflow

**Filters for Searching Files:**
- Include/exclude filters in "Search in Files"
- Scope code search to specific file sets
- Better control over search context

### 3. Crush (Charmbracelet) ✅ NEW RELEASE (v0.57.0)

**Latest Release:** v0.57.0 (April 13, 2026)

**New Features:**

**Fewer Tokens (Preview Feature):**
- New flag reduces size of tool call descriptions by ~98%
- Estimated savings: ~120,000 tokens per session
- Based on observation that modern LLMs understand shorter tool descriptions better
- Opt-in via: `export CRUSH_SHORT_TOOL_DESCRIPTIONS=1`
- Still in preview for testing across more models
- Generally works well for most models according to Crush team

**Session Hardening:**
Two critical fixes to prevent session corruption:

1. **Malformed Image Data Detection:**
   - Crush now detects and gracefully handles malformed image data
   - Prevents session breakage during frontend web development
   - Common issue when using MCP servers (e.g., Figma's MCP)
   - Images no longer crash sessions

2. **Tool Call Streaming Fix:**
   - Previously: Tool calls could fire off during streaming
   - Problem: Tool results without matching tool calls → corrupted sessions
   - Now: Tool calls validated before results, preventing corruption

**Better Skill Discovery:**
- Improved skill parsing and discovery visibility
- Better support for non-Latin contexts (Chinese, Japanese, Korean, Arabic, etc.)
- Community contribution by @huaiyuWangh

**Crush Info Improvements:**
- crush_info tool now shows attribution settings
- Helps model understand current Crush configuration
- Part of Crush's self-awareness system (crush_info + crush_logs + crush-config skill)

**New Provider Support:**
- HYPER_API_KEY environment variable for Hyper authentication
- Provider: Hyper (new addition to 15+ supported providers)

**Additional Improvements:**
- Restored cross-platform instructions in bash tool
- Fixed early events being dropped before initialization
- Added missing strconv import
- Bumped Bubble Tea and Ultraviolet to v2.03

**Sources:**
- https://github.com/charmbracelet/crush/releases

### 1. Apple Xcode 26.3: Native Agentic Coding ✅ MAJOR PLATFORM RELEASE

**Release:** February 26, 2026 (documented in March 2026)

**Significance:**
- First major IDE vendor to make coding agents a **platform-level feature**
- Not just a plugin—built directly into Xcode
- Major shift for Apple development ecosystem

**Features:**
- Native agentic coding support
- Integrates Claude Agent SDK (same harness as Claude Code)
- Integrates OpenAI Codex
- Agents can search documentation
- Explore file structures
- Update project settings
- Capture Xcode Previews for visual verification
- Iterate through builds and fixes autonomously

**Model Context Protocol (MCP) Support:**
- Open standard for connecting agents/tools
- No lock-in to Apple's chosen providers
- Any MCP-compatible agent works with Xcode

**Impact:**
- iOS and macOS developers transition from Copilot autocomplete to full agentic capabilities
- Native integration in their primary IDE
- No need for third-party extensions or separate tools

### 2. Agentic Coding vs Vibe Coding Distinction ✅ CONCEPT CLARIFICATION

**Source:** morphllm.com (March 2026)

**Definition:**

| Dimension | Vibe Coding | Agentic Coding |
|-----------|-------------|---------------|
| **Developer role** | Drives via prompts | Sets goals, reviews output |
| **Autonomy** | Human-in-the-loop every step | Agent plans and executes independently |
| **Error handling** | Human fixes or re-prompts | Agent diagnoses and retries |
| **Best for** | Prototyping, learning, MVPs | Production code, refactors, CI/CD |
| **Typical user** | Non-technical builders, learners | Professional developers, engineering teams |
| **Tool examples** | Bolt, Lovable, Replit Agent, v0 | Claude Code, Cursor, Devin, Codex CLI |
| **Code understanding** | Conversational, per-prompt | Deep codebase indexing, multi-file awareness |
| **Testing** | Manual or user-triggered | Agent runs and iterates on tests |

**Key Insight (February 2026):**
- Andrej Karpathy declared vibe coding passe for professional use
- Replaced with "agentic engineering": not writing code directly 99% of time, orchestrating agents who do
- Academic consensus recommends hybrid architectures: natural language (vibe coding for exploration) + autonomous execution (agentic coding for production)

**Sources:**
- https://www.morphllm.com/agentic-coding-tools
- https://arxiv.org/abs/2505.19443 (academic consensus)

### 5. IDE-First vs Terminal-First Divergence ✅ MARKET SEGMENTATION

**Evidence:**
- **Terminal-First Leaders**: Codex CLI, Crush, Aider, Droid CLI, Claude Code
- **IDE-First Leaders**: Cursor, Windsurf, Antigravity, Google, Amazon
- **Hybrid**: Cursor (IDE + terminal), Jules (IDE + CLI), Cline (IDE + CLI)

**Insight:**
- Clear market segmentation based on developer preference
- Terminal-first: Pure CLI users, DevOps, automation-focused
- IDE-first: Traditional IDE users, UI-dependent workflows
- Hybrid: Flexibility for both preferences

**Differentiation:**
- Terminal: Faster, scriptable, CI/CD friendly
- IDE: Visual debugging, deep integration, lower learning curve
- Hybrid: Best of both, but more complex
