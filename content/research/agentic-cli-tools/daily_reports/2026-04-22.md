### Cursor: App Stability Improvements

**Source:** Cursor Blog
**URL:** https://cursor.com/blog/app-stability
**Date:** April 21, 2026

**Problem Statement:**
- Many users spend entire day using Cursor
- Even rare crashes are extremely disruptive
- Challenge of stability has grown with new features (subagents, instant grep, browser use)
- Most crashes caused by app running out of memory (OOM)

**Results:**
- **OOM-per-session rate:** Down 80% since late-February peak
- **OOM-per-request rate:** Down 73% since March 1

**Architecture:**
- Built on Visual Studio Code and Electron
- Multi-process architecture: renderer processes (editor, agents window) + utility processes (extensions, storage, agent functionality)
- Renderer crashes most severe (completely prevent use of editor), mostly V8 memory limits

**Observability Systems:**
- Every fatal crash reported with telemetry
- Context includes: affected process, crash type, device/app metadata, minidumps, stack traces
- Metrics broken down by app version (per-session and per-request rates)
- Dashboards update within minutes of crash events

**Dual Debugging Strategies:**

**Top-Down:**
- Focus on most memory-intensive features
- Link crash metrics to feature flags in Statsig
- A/B test to measure feature contribution to crash rates
- Track proxy metrics (oversize message payloads correlate strongly with memory issues)
- Attach callstacks to trace oversize messages back to source code
- Add breadcrumbs (metadata logs) for parallel agent usage, tool calls, terminals

**Bottom-Up:**
- Trace individual crash events to root cause
- Crash watcher service in main process
- Uses Chrome DevTools Protocol (CDP) to detect OOM and capture crash stacks in real time
- Patched Electron upstream to obtain stacks without heavy CDP machinery
- Automation runs to reproduce crashes from stacks

**Significance:**
- Demonstrates production-grade engineering discipline at scale
- 80% reduction in OOM crashes significantly improves user experience for all-day users
- Telemetry-driven approach enables rapid detection of regressions
- Electron upstream patches benefit broader ecosystem
- Addresses one of the main pain points for heavy users: stability

### Codex CLI v0.122.0 Stable Release (MAJOR)

**Source:** GitHub Releases
**URL:** https://github.com/openai/codex/releases
**Date:** April 20, 2026

**Previous Version:** v0.121.0 (April 15, 2026)
**Current Version:** v0.122.0

**New Features:**

1. **Standalone Installer Improvements:**
   - Standalone installs are more self-contained
   - Codex app now opens or installs Desktop correctly on Windows and Intel Macs

2. **TUI Side Conversations:**
   - TUI can open /side conversations for quick side questions
   - Queued input now supports slash commands and ! shell prompts while work is running

3. **Plan Mode Fresh Context:**
   - Plan Mode can start implementation in a fresh context
   - Context-usage shown before deciding whether to carry the planning thread forward

4. **Plugin Workflow Enhancements:**
   - Tabbed browsing in plugin workflows
   - Inline enable/disable toggles
   - Marketplace removal
   - Remote, cross-repo, or local marketplace sources

5. **Filesystem Permissions - Security:**
   - Support for deny-read glob policies
   - Managed deny-read requirements
   - Platform sandbox enforcement
   - Isolated codex exec runs that ignore user config or rules

6. **Tool Discovery and Image Generation:**
   - Tool discovery enabled by default
   - Image generation enabled by default
   - Higher-detail image handling
   - Original-detail metadata support for MCP and js_repl image outputs

**Bug Fixes:**
- App-server approvals, user-input prompts, and MCP elicitations disappear from TUI when resolved by another client (no stale prompts)
- Remote-control startup tolerates missing ChatGPT auth
- MCP startup cancellation works through app-server sessions
- Resumed and forked app-server threads replay token usage immediately
- Security-sensitive flows tightened: logout revokes managed ChatGPT tokens, project hooks and exec policies require trusted workspaces, Windows sandbox setup avoids broad user-profile and SSH-root grants
- Sandboxed apply_patch writes work correctly with split filesystem policies
- File watchers now notice files created after watching begins
- Several TUI rough edges fixed: fatal skills-list failures, invalid resume hints, duplicate context statusline entries, /model menu loops, redundant memory notices, terminal title quoting in iTerm2

**Documentation:**
- Added security-boundaries reference to SECURITY.md (sandboxing, approvals, network controls)
- Documented custom MCP server approval defaults and exec-server stdin behavior
- Updated app-server docs for plugin API changes, marketplace removal, resume/fork token-usage replay, warning notifications
- Added short guide for responses API proxy

**Chores:**
- Split plugin and marketplace code into codex-core-plugins
- Moved more connector code into connectors
- Continued breaking up large core session/turn modules
- Refactored config loading and AGENTS.md discovery behind narrower abstractions
- Stabilized Bazel and CI with flake fixes, native Rust test sharding, scoped repository caches, stronger Windows clippy coverage, updated rules_rs/LLVM pins
- Added core CODEOWNERS and smaller development build profile
- Removed stale core models.json, updated release preparation to refresh active model catalog

**Significance:**
- Major security and permissions enhancements show enterprise-grade focus
- Deny-read policies allow enterprises to restrict access to sensitive code/files
- Side conversations improve workflow (quick questions without disrupting main task)
- Plugin workflow improvements (tabbed browsing, local marketplaces) increase extensibility
- Tool discovery and image generation by default lower friction for new users
- Security tightening (logout revokes tokens, workspace trust) addresses enterprise compliance
- Active refactoring and modularity improvements suggest long-term maintainability focus
