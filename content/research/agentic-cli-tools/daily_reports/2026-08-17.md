# Daily Report — August 17, 2026

## New Findings

### Claude Code — Triple Release Weekend: v2.1.229, v2.1.231, v2.1.232, v2.1.233 (August 12–14, 2026)

Four releases in 72 hours after the extended silence that ended August 11. The sprint was stabilization-heavy with notable security content:

**v2.1.233 (August 14):**
- GitLab merge request URLs now work with `--worktree` and display in `claude agents` view as `!N`
- New opt-in `forward_user_identity` apps gateway setting sends signed-in user identity as headers for per-user spend attribution — enterprise teams can finally track spend per developer
- New `CLAUDE_CODE_TOOL_MEMORY_LIMIT` env var enables Linux memory cgroups for Bash tool commands — runaway builds can no longer stall sessions
- `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` allows tuning WebFetch cache TTL (default unchanged at 15 minutes)
- **NTLM credential-leak vector patched**: Windows paths spelled with the NT `\\??\` device prefix bypassed UNC path validation — now blocked
- PowerShell permission bypass on `$PSDefaultParameterValues` also patched
- Todo/task tools (TaskCreate/Get/Update/List, TodoWrite) are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer models — set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` to restore

**v2.1.232 (August 13):**
- **Subagent forking now ON by default**: `subagent_type: "fork"` inherits full conversation and prompt cache; non-teammate agent spawns in interactive sessions now run in background by default
- **Cross-session @ mentions**: Type `@` in prompt to mention another Claude session by name — Claude uses `SendMessage` to reach that session directly
- `SendMessage` now delivers to bare session names that exactly match a live session (no confirmation needed)
- Unique session names enforced across machines — duplicate names get `name-word-word` variant
- GitLab token redaction expanded: `glrt-`, `gloas-`, `glptt-`, `glagent-`, `glimt-`, `glsoat-`, `glcbt-`, `glft-`, `glffct-` families; full redaction of `glpat-`/`gldt-`; `glab` CLI config gets sandbox + credential-path protection like `gh`
- GitLab added to plugin marketplaces: bare `gitlab.com` repo URLs clone like `github.com`
- Windows permission bypass patches: PowerShell variable-writing parameters silently overwrote `$PSDefaultParameterValues`; Git Bash followed Cygwin-style symlinks that bypassed path validation
- `/code-review` at high/xhigh/max effort now runs as background subagent (matching other effort levels)

**v2.1.231 (August 13):** Fixed MCP OAuth sign-in failing with redirect URI mismatch for servers using pre-registered OAuth clients (e.g., Slack).

**v2.1.229 (August 12):**
- SSE keepalive pings added to gateway streaming responses during long thinking pauses — prevents idle-timeout disconnects on Vertex and Bedrock
- Plugin marketplace `command` sources: local commands can print plugin directory, re-resolved each session without restart; `mode: "link"` uses it in place
- `ListAgents` now marks disconnected Remote Control sessions as `offline` and labels cloud sessions as `cloud`
- Auto mode regression fixed: was failing on every tool call for users who disabled attribution header via `CLAUDE_CODE_ATTRIBUTION_HEADER`
- `/feedback` and `/bug` now open immediately when invoked while Claude is responding

## Community Pulse

**Working well:** Cross-session messaging via @ mentions is a quality-of-life win for developers running multiple Claude Code sessions simultaneously — the `SendMessage` integration means less tab-switching and no copy-paste. Subagent forking on by default should reduce friction for multi-agent workflows.

**Problems:** The pattern of Todo/Task tools being stripped from newer Claude models (Opus 4.8+, Sonnet 5, Fable 5, Mythos 5+) continues — `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` opt-out is increasingly required post-launch. The Windows NTLM credential-leak vector patched in v2.1.233 is a reminder that path-validation edge cases in credential-handling subsystems remain a live attack surface.

**Interesting:** The three-peat of subagent permission fixes across Kilo and Claude Code in the same week — Kilo fixing phantom deny rules that blocked explicitly allowed subagent commands, while Claude fixed the readOnlyBash ceiling projection — suggests teams are converging on the same failure mode independently. The fix surfaces a design question: when a parent agent has restricted bash, should child agents inherit those restrictions or operate on their own configured permissions?
