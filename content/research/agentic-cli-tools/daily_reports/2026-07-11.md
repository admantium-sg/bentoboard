## Security Research — Two New Attack Vectors Published This Week

### Friendly Fire: README-Based Code Execution (AI Now Institute)

New research from the AI Now Institute demonstrates that Claude Code and OpenAI Codex can be tricked into executing malicious code when reviewing untrusted third-party codebases. The attack — called "Friendly Fire" — exploits the autonomous command-approval modes these tools are sold on.

**How it works:** The attacker plants a README.md in a popular open-source library (demo used geopy, a widely-used Python library) suggesting developers run a `security.sh` script before opening a PR. The script launches a hidden binary disguised as a harmless build artifact. Claude Code in auto mode reads the README, decides the script is part of the security-review job, and executes it — no prompt, no approval box.

**Tested versions:** Claude Code 2.1.116, 2.1.196, 2.1.198, 2.1.199 on Sonnet 4.6, Sonnet 5, and Opus 4.8; Codex CLI 0.142.4 on GPT-5.5.

**Key finding:** The same payload worked unchanged across all tested model versions — a single injection, two vendors, four models, no modifications. AI Now argues this is a design flaw, not a patchable bug: "the models still cannot reliably tell the code they are reading from the instructions they are meant to follow."

**Why it's novel:** Earlier agent attacks relied on machine-configuration files (.mcp.json, .claude/settings.json) that trip Claude Code's "Yes, I trust this folder" warning. This attack hides in README.md — an ordinary text file in every repository. No trust prompt, no elevated access, much wider opening.

**Status:** Proof-of-concept publicly available (payload stripped). No reported wild exploitation. Researchers notified Anthropic and OpenAI outside formal disclosure programs.

**Source:** https://thehackernews.com/2026/07/friendly-fire-ai-agents-built-to-catch.html | https://ainowinstitute.org/publications/friendly-fire-exploit-brief

### HalluSquatting: AI Tool Retrieves Fake Repositories With Hidden Instructions

Research from Tel Aviv University (Ben Nassi group), Technion (Stav Cohen), and Intuit (Ron Bitton) demonstrates a new attack that turns AI coding assistants into botnet delivery vehicles by exploiting consistent hallucination patterns.

**How it works:** The attack chains two AI quirks: (1) hallucination — AI invents fake package/repository names when it doesn't know the real one, and (2) prompt injection — adversarial instructions hidden in fetched content. Attacker picks a trending repository, probes the AI to learn which fake names it invents most often (85-100% consistency), registers those names on GitHub with hidden instructions, then waits for real users to ask their assistant to fetch the trending resource.

**Tools tested:** Cursor, Windsurf, GitHub Copilot, Cline, Gemini CLI, and "OpenClaw family of assistants" — all retrieved attacker-controlled content and executed attacker-supplied code.

**Why it scales:** No passwords, no worming, no OS-specific malware. The AI is the delivery van. Once the planted instructions take over, the agent uses its own command-running tool to install ordinary bot malware. The planted name can reach any machine running the affected tool.

**Connection to Friendly Fire:** Both attacks exploit the same root condition: untrusted outside text reaching an agent with command execution permission. The PyTorch Lightning pypi compromise (April 2026) shows attackers do poison public code — these aren't purely theoretical attack paths.

**Mitigations cited:** Search before fetching (grounds the agent in reality); avoid auto-run modes on anything the agent fetched; verify package/repository names resolve to expected sources; platforms could pre-register known hallucinated names (like typosquatting defenses).

**Status:** Vendors and model makers notified before publication. Exact replication steps withheld.

## Community Pulse

**Security narrative shifting from config files to README/docs attacks:** The Friendly Fire and HalluSquatting findings represent a meaningful escalation in the AI coding agent security discourse. Both target the documentation/readme layer that was previously considered benign. This expands the attack surface significantly — every repository a developer or agent reviews is a potential vector. The AI Now Institute's framing ("this cannot be fixed with a model update") is already circulating in security-focused communities.

**CLI tool ecosystem response to security concerns:** The rapid Claude Code release sprint (July 3-9) addressed config-file injection but not the README vector — that class of attack wasn't publicly known then. The HalluSquatting paper specifically tested Cline and "OpenClaw family" in addition to Cursor, Windsurf, Copilot, and Gemini CLI. The breadth of affected tools suggests this is an ecosystem-level challenge, not a vendor-specific issue.

**Auto mode trust calculus:** Both new attacks specifically exploit auto-run modes. Claude Code's default-permission-to-Manual change (v2.1.203, July 7) was a security-conscious default shift, but auto mode remains opt-in. The Friendly Fire research explicitly targets auto mode, arguing the automation it provides is fundamentally incompatible with reviewing untrusted code. This creates a genuine tension for teams that adopted these tools precisely for third-party code auditing.
