### Crush CLI v0.62.0 Release (MAJOR)

**Source:** GitHub Releases
**URL:** https://github.com/charmbracelet/crush/releases
**Date:** April 22, 2026

**Release Notes:** "Crushing the system prompt...and more!"

**Major Feature: 98% Token Reduction**

1. **Short Tool Descriptions Now Default:**
   - System prompt now uses vastly shorter tool instructions
   - Saves approximately 120,000 tokens per session
   - Previously preview feature in v0.57.0, now default
   - Opt-out available with `export CRUSH_SHORT_TOOL_DESCRIPTIONS=0` (but may be removed)
   - Benefits: Cost savings, better performance for small/local models with limited context windows

2. **Fetch Tool Size Reduction:**
   - Previous limit: 5MB (described as "sort of crazy")
   - New limit: 100KB (truncated if exceeded)
   - For larger content: download tool available
   - Particularly important for small models to prevent context window overflow

3. **Automatic Diff Rendering:**
   - Crush now automatically detects diff-like output
   - Renders as diff even when from non-edit tools (e.g., GitHub MCP server)
   - Improves readability for diff content from any source

4. **Log Cleanup:**
   - Removed noisy warnings about skill discovery from logs (`crush logs -f`)
   - Cleaner log output for developers

### Factory AI: Droid Computers Product Announcement (MAJOR)

**Source:** Factory AI Blog
**URL:** https://factory.ai/news/droid-computers
**Date:** April 22, 2026

**Product Overview:**
"Persistent machines for remotely orchestrating Droids. Spin one up in Factory's cloud, or turn your own machine into a Droid Computer."

**Key Features:**

1. **Persistent Environments:**
   - Droid returns to real development environment with filesystem, configuration, credentials, local services, and process memory intact
   - No need to reconstruct environment each session
   - Droid starts right where it left off
   - Continues running in cloud even after laptop closed

2. **Run Anywhere, Anytime:**
   - Mobile access: Open Factory platform on phone to manage Droids on the go
   - Remote orchestration: Control Droids on laptop/workstation from anywhere
   - Asynchronous workflows: Kick off task before sleep, have result ready in morning
   - Background execution: Continue tasks while away from desk

3. **Always-On Agents:**
   - Combine Droid Computers with automations to build persistent agents
   - Droid can watch for alerts, triage customer issues, conduct deep research tasks in background
   - Same environment with context from previous sessions enables pattern recognition
   - Self-improvement: Droid can suggest better tooling, prioritize tasks more effectively

4. **Paradigm Shift:**
   - **Ephemeral Sandboxes (Old Paradigm):** Clean, isolated, easy to throw away; work well for short, one-off tasks in simple environments
   - **Persistent Environments (New Paradigm):** Required for complex, stateful software engineering workflows beyond simple coding
   - Persistent homes enable: Environment maintenance, context storage, self-improvement across sessions
   - Industry convergence: Powerful agents need persistent environments

5. **Two Setup Paths:**

   **Managed Computers:**
   - Cloud development environments hosted and managed by Factory
   - Factory provisions machine, installs Droid, sets up Git credentials
   - Droid sets up dev environment dynamically, or user configures via terminal
   - Stay online while Droids work, pause when idle (charged only while awake)
   - Resume with full filesystem and memory snapshots

   **Bring Your Own Machine (BYOM):**
   - Register any machine as Droid Computer (laptop, Mac Mini, workstation, VM)
   - Useful for: Private networks, self-hosted infrastructure, pre-configured dev environments
   - Already in production at several Fortune 500 companies
   - Connects outbound to Factory backend, no additional networking config

6. **Availability and Pricing:**
   - **Bring Your Own Machine:** Free for all users
   - **Managed Computers:** Available for Max, Growth, and Enterprise plans

**Significance:**
- First major agentic CLI tool to offer persistent cloud environments
- Addresses fundamental limitation of ephemeral sandbox approach
- Enables multi-day autonomous workflows with state preservation
- BYOM free tier lowers barrier to entry
- Persistent environments represent paradigm shift in cloud agent architecture
- Aligns with industry trend: agents need stateful environments for complex workflows
- Combines with Factory's existing Missions architecture for end-to-end autonomous development
- Competitive advantage: Other tools (Cursor, Codex, Kilo, Crush) still use ephemeral contexts

### Factory AI: How Missions Work Architecture Article (Previously Missed)

**Source:** Factory AI Blog
**URL:** https://factory.ai/news/missions-architecture
**Date:** April 10, 2026

**Note:** This article was published on April 10, 2026, before the last research check (April 22, 2026), but was not captured in previous findings. Adding for completeness.

**Key Concepts:**

1. **Problem: Agent Context Window Limitations:**
   - Most real projects are too broad and complex for single context window
   - As agent sees more, it becomes less focused and reliable
   - Two failure modes: Irrelevant context accumulates, adversarial context accumulates

2. **Design Principles:**

   **Separation of Concerns and Incentives:**
   - **Orchestrator:** Plans and decomposes approach, steers execution to completion, passes validation gates
   - **Workers:** Complete well-specified features with clear success criteria, iterate until correct, hand off for validation
   - **Validators:** Evaluate completed work for correctness and completeness, surface bugs and gaps, don't implement fixes

   **Test-Driven Development at Two Levels:**
   - Each worker writes tests before code
   - At mission level, orchestrator defines correctness first (validation contract), then creates features

   **Externalized State:**
   - No single agent holds complete picture
   - State distributed across shared artifacts: validation contract, feature list, research notes, operational guidelines

   **Model Specialization:**
   - Different models for different roles: broad planning for orchestrator, reliable execution for workers, thoroughness for validators

3. **The System:**
   - User describes goal → Orchestrator investigates and clarifies requirements
   - Orchestrator writes validation contract (behavioral assertions defining success)
   - Work decomposed into features → grouped into milestones
   - Shared state files created (boundaries, procedures, knowledge base)
   - Programmatic runner spawns workers for each feature
   - Workers start fresh, receive feature spec, write tests first, implement
   - Milestone validation using fresh agents (scrutiny validators + user-testing validators)
   - Validation loop repeats until milestone passes

4. **Real-World Example:**
   - **Mission:** Slack clone (auth, channels/threads, real-time messaging, reactions, mentions, file uploads, search, presence/notifications)
   - **Results:** 38.8k lines of code (52.5% tests), 89.25% statement coverage
   - **Process:** 6 milestones, 2-4 validation rounds each
   - **Impact:** Validators surfaced 81 issues, orchestrator generated 21 fix features (34.4% of implementation work)
   - **Efficiency:** Median run lengths: 51 turns (implementation), 30 turns (validation)

**Significance:**
- Missions architecture enables multi-day autonomous software development
- Validation-based approach ensures correctness
- Separation of concerns prevents adversarial context accumulation
- Model specialization optimizes for different roles
- Test-driven development at two levels ensures quality
- Real-world example demonstrates viability (Slack clone with 89.25% coverage)
- Validation accounting for 37.2% of total runtime shows rigorous quality focus
- Available today via `/missions` command in any Droid session

## Market Trends and Industry Insights

### Factory AI's Droid Computers: Paradigm Shift to Persistent Environments

1. **Ephemeral vs Persistent:**
   - **Ephemeral (Current Industry Standard):** Clean sandboxes for short, simple tasks (Cursor, Codex, Kilo, Crush)
   - **Persistent (Factory AI Innovation):** Long-lived environments for complex, multi-day workflows

2. **Competitive Advantage:**
   - First-to-market with persistent cloud environments for coding agents
   - Enables workflows impossible with ephemeral sandboxes (multi-day development, state preservation, self-improvement)
   - BYOM free tier lowers barrier to entry

3. **Industry Convergence:**
   - "The broader industry has begun to converge on a similar intuition this year: powerful agents need persistent environments"
   - Suggests other tools may follow with similar capabilities

4. **Implications for Competitors:**
   - Cursor, Codex, Kilo, Crush still use ephemeral contexts
   - May need to develop persistent environment capabilities to remain competitive for complex workflows
   - Persistent environments could be next battleground for enterprise features

### Codex's Amazon Bedrock Integration: Multi-Provider Strategy

1. **Enterprise Focus:**
   - Built-in Amazon Bedrock integration signals enterprise emphasis
   - Expands model options beyond OpenAI's offerings
   - Addresses enterprise requirements (AWS ecosystem, data residency, procurement)

2. **Competitive Positioning:**
   - OpenAI leveraging multiple clouds/partners (Azure, AWS via Bedrock)
   - Different from pure OpenAI-only approach
   - May pressure competitors (Cursor, Kilo, Crush) to expand provider support

3. **Multi-Provider Trend:**
   - Codex now supports: OpenAI models, Amazon Bedrock, and potentially other providers
   - Crush has provider-agnostic design (Hyper, custom providers)
   - Cursor emphasizes model flexibility (different models for different tasks)
   - Kilo supports custom providers and model variants

### Crush's Token Efficiency: Cost and Performance Optimization

1. **98% Token Reduction:**

2. **Industry Trend:**
