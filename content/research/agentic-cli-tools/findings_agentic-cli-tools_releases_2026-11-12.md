### SECURITY ADVISORY (new, not previously covered): Claude Code TOCTOU race in Edit tool allows writes outside the workspace — CVE-2026-88968
**GHSA-5xjx-9qx6-jcrv**, severity **high**, published **2026-11-09T22:42:03Z** (just before the window — labelled as a catch-up item; it had **not** been recorded in this project's cumulative findings or any daily report, so it is new content). Claude Code validated Edit-tool targets using point-in-time pathname and symlink resolution **not bound to directory inodes or file descriptors**. On **macOS**, a process running inside Claude Code's **Bash sandbox** could win the time-of-check-to-time-of-use window by atomically swapping an in-workspace parent directory for a symlink after validation, causing the **unsandboxed Edit implementation to overwrite an attacker-selected user-writable file outside the workspace**. Exploitation requires running attacker-controlled code inside the sandbox (e.g. via a **malicious repository or dependency script**). Fixed in **v2.1.251**; users on standard auto-update received the fix automatically, manual updaters should update manually. Credited to **hackerone.com/mahoraga007 (Sunder Singh)**. ### Google launches Gemini Decisions API + new Gemini Decision 1 model — $0.10/1M input tokens, $0 output
Google introduced the **Gemini Decisions API**, a new Gemini API endpoint powered by a **new model, `gemini-decision-1`** ("Gemini Decision 1"). It evaluates **up to 1,000 independent questions in a single request** — yes/no, multiple-choice and rubric-scoring — against one shared **multimodal input** (text, images, audio, video, PDFs; **up to 256K tokens**), returning **probabilities and confidence scores (0–1)** without token-by-token decoding. Key numbers: **150–250 ms end-to-end latency**, **50–100 ms median model compute**, **$0.10 per 1M input tokens with zero output tokens billed**, and Google claims it is **~5x cheaper** than Gemini 3.5 Flash-Lite on the Interactions API for the same benchmark suite. The shared input is billed **once per request** regardless of question count; no variable thinking-token bills and no separate audio/OCR costs. Google says Gemini Decision 1 **leads its benchmarks across agent routing, reasoning, ranking and multimodal understanding, with the lowest calibration error**. Stated use cases are explicitly agentic: **tool selection, policy checks, model routing and context grading**, with confidence scores used to route ambiguous cases to a fallback or a human reviewer. Ecosystem integrations rolling out across **OpenRouter, LangChain, Vercel, LiteLLM, Pydantic AI, Pipecat, LiveKit and OpenCode** plus the `google-genai` SDKs; Gemini in Google Cloud "coming soon". Available now via API key in **Google AI Studio** (`client.decisions.create(model="gemini-decision-1", ...)`), with Python/JS/REST guides and demo apps (Doorstep Parcels, Speed Sketch, Find the Zoo Keeper). Google cites **Stitch Rapid** using it to design a product flow in seconds (1x speed).

### SECURITY (major, new): Depi researchers demonstrate prompt-injection → sandbox-escape → npm backdoor chain against OpenAI Codex CLI
Security firm **Depi** (Pierre Martin "Worty", Garance de la Brosse "Madder") published **"Backdooring the next release of Codex through GitHub Action pipeline exploit chaining"** on **2026-11-11**, describing a proof-of-concept exploit chain against the **`openai/codex`** GitHub repo that reached the publishing pipeline of the real npm package **`@openai/codex`** — "not a demo package… the real package". Chain: (1) the **Issue Labeler** GitHub Actions workflow `.github/workflows/issue-labeler.yml` fed attacker-controlled issue title/body into the Codex agent with `openai/codex-action@… # v1.7` and **`allow-users: "*"`**, so any GitHub user could trigger it — a prompt injection; (2) the injected shell commands stayed in the sandbox but **exposed .NET debugging pipes (CoreCLR `DebuggerIPCControlBlock`/DCB) in a shared temp dir** let the researchers read the **memory of the GitHub runner process**, recovering credentials that had been removed from the agent's environment; (3) a stolen token poisoned a **GitHub Actions build cache**, planting a Python test into a separate Rust testing workflow with broader permissions; (4) a maintainer **deleting a fake release** would trigger an attacker-created workflow to mint an **OIDC identity token trusted by npm**, enabling publication of a malicious `@openai/codex` version. Reported via **Bugcrowd**; **OpenAI deployed a fix immediately**; initial bounty **$1,000** (still under review, against a policy listing up to **$100,000** for critical). **No malicious release was published and no affected users identified**; the write-up gives **no affected Codex CLI version and no fix date**. Depi also notes its cache-poisoning step is already defeated by GitHub's **2026-06-26 read-only Actions cache for untrusted triggers** change, and that with auto-update enabled "you don't get a vote" — it recommends a cooldown on auto-updating agent tooling. The Defiant covered it on **2026-11-11T16:41:44Z** ("Researchers Say Codex Flaw Put npm Releases at Risk", published 2026-11-11T15:37:06Z) and cited **~96.8 million downloads of `@openai/codex`** from Oct 12–Nov 10 via the npm downloads API.
Source: https://depi.security/blog/20261111-backdooring-codex/ (full body retrieved) · https://thedefiant.io/frontier/ai/researchers-say-codex-flaw-put-npm-releases-at-risk (full body retrieved) · https://github.com/openai/codex/blob/main/.github/workflows/issue-labeler.yml
Published: 2026-11-11 (Depi post) / 2026-11-11T15:37:06Z (The Defiant)
Note: **Genuinely new, in-window, not previously covered** in this project. This is the most consequential in-window item for agentic CLI risk: an agentic coding tool used *inside* a repo's CI is itself an injection target whose sandbox can be escaped via host debugger IPC, converting an "AI helper" into a supply-chain pivot. **No OpenAI advisory or CVE identified as of window close** (GitHub Advisory API shows nothing new for `@openai/codex`); OpenAI's own position per Depi is that "there is nothing you need to patch on your side."

### Grok Build "GhostShares 2" — verified primary-source figures from Claroc (adds precision to the earlier finding)
The primary source behind the Grok Build disclosure was retrieved in full this cycle: security firm **Claroc**, **"GhostShares 2: Grok Apps Exposed xAI's Business Secrets and People's Private Data"** (`https://blog.claroc.io/ghostshares-grok-build-apps/`, published 2026-11-10). Claroc (Founding Hackers **Pierre Martin "Worty"** and **Garance de la Brosse "Madder"** — the same pair behind the Depi Codex disclosure) tried **43,551 Grok app addresses** under `grok.me`; **37,571 were still online** and **35,578 (94.7%) opened for anyone with no sign-in** (only **1,993 / 5.3%** returned HTTP 401, the "Only you / Invited users" response). **24** open apps were built by **SpaceXSI** and **X** staff — a confidential onboarding plan for a new enterprise-sales hire (systems to access in week one, internal system addresses, **19 internal chat channels**, a 30-day plan), a **sales territory map of 594 strategic accounts** with pipeline, **eight X advertising proposals/media plans** including one to a **US federal agency** marked confidential, **four live advertiser account boards** with campaign spend (one tracking progress toward a **$1.6M sales goal**), **seven campaign reports** for advertisers in Brazil, Japan, Korea and Thailand, and **two copies of an X brand-safety playbook** labeled an internal sales hub. Beyond SpaceXSI/X, the open apps exposed data from **30 identifiable organisations, 26 with more than 1,000 employees, six in the Fortune 500**. Claroc's root-cause explanation is architectural: published Grok Build apps get **their own hostname** (like `cinder-crane-sand-frost.grok.me`) rather than a secret path segment, so **DNS enumeration** makes them discoverable — the opposite of Claude's `claude.ai/public/artifacts/<id>`, ChatGPT's `chatgpt.com/share/<id>` and Gemini's `gemini.google.com/share/<id>`, where the secret lives in the path. Claroc notes the same "GhostShares" pattern found **Meta's Muse** last month. SpaceXSI took its 24 apps down within hours of Ars Technica's emailed questions and of Claroc's Nov 8/9 notification (Claroc notified SpaceXSI on Sunday, Nov 8, then tagged Musk and Grok Manager **Matt Palmer** on X after no response), but **did not remove the apps other users and organisations left open**; no xAI advisory or CVE exists.
