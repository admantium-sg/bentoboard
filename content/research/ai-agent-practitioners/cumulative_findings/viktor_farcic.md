# Cumulative Findings — Viktor Farcic

_Updated: 2026-11-27 · 35 tracked items_

## Highlights

- **2026-11-23 · The thesis is a reversal: "I am the metrics" is what supervising one agent used to feel like** — and it stopped being true the moment dozens of agents ran overnight. The 41 problems are framed as the price of moving from watching one agent to managing a fleet.
- **2026-11-23 · The dead-alarm example is the strongest argument in the piece** — a CI alert whose secrets were never registered fired for seven weeks and reached nobody, with main red for nineteen hours. Nothing here is an agent failure; it is a fleet failure that only aggregation surfaces, and no human was watching to see it.
- **2026-11-23 · The line that generalises beyond the anecdote: "when agents write the code, they also write the tests, the build scripts and the CI"** — so the agents that follow inherit the debt and cannot complain. The feedback a supervised setup gets for free has to be rebuilt as instrumentation.
- **2026-11-23 · Four layers of required instrumentation, with a metadata-only rule** — the run (status changes, human interventions, hand-offs), every shell command as a span, the surrounding pipeline (checks, CI, reviews, main green), and per-run CPU/memory/disk, all sharing one run ID, with no prompts, no file contents and no agent output retained.
- **2026-11-23 · He places telemetry above evals and explains the split** — evals are to agents what tests are to applications, whereas telemetry is what happens on real work, including problems like the dead alarm that have nothing to do with the agent. Most coding agents already speak OpenTelemetry (Claude Code, Codex, OpenCode, Pi), so the work is gluing layers together, not instrumenting from scratch.
- **2026-11-23 · Article and video shipped the same day, and the argument is deliberately tool-agnostic** — the long-form piece is the argument, the video the demo, and both are written so the practices transfer to readers who are not running his stack.
- **2026-11-16 · The KAOP piece poses the question his whole agent-fleet work has been circling: why put a platform between an agent and a Kubernetes cluster?** — Claude Code alone fixes clusters fine; the problem only appears when it is a company, with production credentials spread across laptops, nobody approving what agents change, and no shared record of what they did or what it cost. He states the trade-off plainly instead of assuming the platform wins.
