## Harrison Chase

### LangChain blog (1)

- **2026-11-11** [How our GTM Agent builds consistent, high-quality sales artifacts](https://www.langchain.com/blog/gtm-agent-high-quality-sales-artifacts) — Over 12 weeks the internal GTM Agent generated 1,540 sales artifacts (account plans, proof-of-value docs, proposal decks, onboarding plans) at 100+ per week, saving reps 337 hours on the artifacts that actually got sent. The headline is a matched comparison: 47% of deals with an artifact moved to a later stage versus 16% of matched deals without one, and 46% of artifacts were followed by a customer call within 14 days. The design point: the hard part was never the model — it was capturing process knowledge (which artifact clears which deal gate), customer context (Salesforce record, usage data, call transcripts), voice and brand guidelines, and wiring stage gates so a missing step surfaces while the deal is still live instead of weeks later in pipeline review. Stack: skills versioned separately from code, a sandbox with Office tools so the agent can build, render, inspect and fix its own document, a Slack surface reps already use, and scheduled runs on Deep Agents / Managed Deep Agents.

- **2026-11-11** [Gemini Decisions API](https://simonwillison.net/2026/Nov/11/gemini-decisions-api/) — Google joins Jev and OpenAI with "Gemini Decision 1", an API almost identical to Jev: the same three question types (yes/no, choice, rubric-scoring) and Jev's own "Noul" term reused for yes/no. Priced like GPT-6 Luna's decision model at $0.10/M input with output free, while Jev stays cheapest at $0.042/M. Gemini Decision 1 is the only one of the three that is fully multimodal — text, images, audio, video, PDFs — which Simon tested by throwing his Yonkers stomping-robot video at it with dragon/robot/france/usa questions. The behavioural difference is in the answer shape: Jev and OpenAI return 1.0 or 0.0, Gemini returns calibrated probabilities (0.049 for dragon, 0.923 for robot, 0.083 for France, 0.923 for USA).
- **2026-11-11** [aws-emulator](https://simonwillison.net/2026/Nov/11/aws-emulator/) — AWS finally ships an official local emulator for its services, so tests can run against a local clone without provisioning a paid API key. Written in Rust by "a huge swarm of agents": 29,684 commits in the first three weeks, per Swaminathan Sivasubramanian's guest post on Werner Vogels' blog. Simon's caveat is a deployment one — it currently requires Docker on macOS and Windows, and he would rather have a single binary droppable into a test suite in any language.
- **2026-11-11** [Browse tools.simonwillison.net by tag](https://simonwillison.net/2026/Nov/11/tools-tags/) — A browsing layer over Simon's collection of 244 vibe-coded tools, built by spending leftover Fable 5.2 credits and pointing tree-sitter at each tool's source to extract the JavaScript APIs, libraries and web API hosts it uses. The homepage now shows tag clouds by category (Marked 12, Pyodide 11, DOMPurify 7, Leaflet 4, three.js 3, Chart.js 2 and so on), so the collection can be navigated by stack instead of by scrolling.
- **2026-11-11** [llm 0.37.2](https://simonwillison.net/2026/Nov/11/llm/) — Security release fixing two advisories reported by Daniel de Araujo: GHSA-v9h7-jj4g-f862 and GHSA-r639-rr7r-x72w. Both concern the OpenAI-compatible endpoint mechanism — a configured OpenAI API key could be sent to a third-party provider either when the key named by `api_key_name` had never been stored, or when a `responses: true` model was run with `-o chat_completions 1`. `extra-openai-models.yaml` is now managed via the 0.37 `llm openai endpoint add` command.
