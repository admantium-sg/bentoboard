## New Findings (July 18-20 Batch — 7 Novel Papers)

### 1. SWE-Pruner Pro: Self-Pruning Inside the Coding Agent
**arXiv:2607.18213** — cs.CL, cs.SE | July 20, 2026

Agents encode internal representations indicating code relevance when reading tool output. SWE-Pruner Pro uses a small head turning those internal states into keep-or-prune labels per line, with a length-aware embedding keyed to each tool output's line count.

Results: up to 39% prompt and completion token savings; SWE-Bench Verified resolve rate improves +3.8%; long-context Oolong accuracy improves +2.2pp. Bounded inference overhead.

Notable: achieves token savings AND accuracy improvement simultaneously — unlike most compression approaches that trade off quality.

**Significance:** Self-pruning inside the agent's own representations (not external classifier) is the novel mechanism; practical for coding agent deployment.

---

### 2. Automated Discovery Has No Universally Superior Harness
**arXiv:2607.18235** — cs.CL, cs.AI | July 20, 2026

3.1M+ LLM rollouts across 30 budget-matched harnesses and 12 model-problem pairs. No fixed harness is reliably superior across all setups. OpenEvolve variants generally underperform simpler alternatives.

Key implication: harness choice is a hyperparameter to be tuned per problem/model, not a universal recipe. Adaptive allocation (start multiple, prune weak partial runs, reallocate to survivors) outperforms both fixed and non-adaptive ensemble approaches.

**Significance:** Shifts philosophy from "find the best harness" to "adaptively allocate budget guided by early performance signals."

---

### 3. VDAR-Router: Difficulty-Aware LLM Routing
**arXiv:2607.18098** — cs.CL | July 20, 2026

Training-free routing via explicit query difficulty analysis + retrieval of historical examples with similar difficulty profiles. Routes each query to appropriate model under cost-performance tradeoff.

Core claim: surface semantics / embedding similarity routing ignores underlying query difficulty. Explicit difficulty analysis + retrieval of similar historical cases enables better model selection.

Results: better cost-performance tradeoffs than surface-based routing across three datasets.

**Significance:** Practical cost optimization for multi-model deployments without training; difficulty-aware selection as the routing signal.

---

### 4. Expressions of Belief: Prompt Engineering Under Linguistic Framing
**arXiv:2607.18232** — cs.CL, ACL 2026 | July 20, 2026

Typology of how users express beliefs to LLMs — 17 fine-grained types across form, evidentiality, epistemic stance, and tone. 16 LLMs evaluated (Llama3, Qwen3, Gemma3; 1B–30B; base vs instruct).

Key findings: bigger models and instruction-tuned models tend to be less context-following (more skeptical of user belief expressions) than smaller/base models. Specific EoB types statistically significantly persuade LLMs more than others.

**Prompt engineering relevance:** linguistic framing of belief-expressions affects model compliance; implications for robust prompt design.

---

### 5. Answer-Conditioned CoT Degrades Reasoning Distillation
**arXiv:2607.14552** — cs.CL, cs.AI | July 16, 2026

Standard CoT distillation: when sampling fails, show gold answer + ask model to write chain reaching it. This paper shows answer-conditioning degrades data quality — correctness filtering cannot detect the damage.

Training on own answer-conditioned chains lowers verifiable-reasoning accuracy by up to ~27pp on hardest competition problems. Chains rationalize backward from shown answer; early final-answer statement is the measurable symptom.

**Key takeaway:** generate answer-blind; no correctness filter can see this damage.

**Significance:** Practical guidance for CoT distillation pipelines — answer-conditioning is harmful even when the resulting chain reaches the correct answer.

---

### 6. OS-Pruner: Optimal Stopping for CoT Pruning
**arXiv:2607.11089** — cs.AI | July 13, 2026

Formulates CoT pruning as optimal stopping: given a reasoning prefix, learns whether further reasoning is worth its token cost. 20–60% generation length reduction with minimal accuracy sacrifice. Lightweight at training and inference time; user-controllable accuracy-effort tradeoff.

**Significance:** Different from CAID/PACE approach — optimal stopping specifically, with explicit utility tradeoff formulation.

---

### 7. CAID / PACE: Information-Theoretic CoT Efficiency
**arXiv:2607.11266** — cs.AI, Findings ACL 2026 | July 13, 2026

Identifies valid-but-inefficient CoT steps (circular reasoning, excessive decomposition) that existing step evaluators miss. CAID (Context-Aware Information Density): training-free information-theoretic metric.

PACE: post-hoc compression using CAID. Reduces token consumption 31–53% while maintaining accuracy across GSM8K, StrategyQA, ARC-Challenge.

**Significance:** 31–53% token reduction without accuracy loss; CAID is a new training-free diagnostic metric for CoT quality.
