## Task 1: arXiv Papers (cs.CL, cs.LG, cs.AI)

### 1. Orchard: Open-Source Agentic Modeling Framework
**arXiv:2605.15040** (May 14, 2026) — Baolin Peng et al. (Microsoft Research)
- **Problem:** Open research constrained by infrastructure and training gaps; most open-source frameworks focus on orchestration/evaluation, not scalable agent training
- **Contributions:**
  - **Orchard Env:** Lightweight environment service with reusable primitives for sandbox lifecycle management across task domains, agent harnesses, and pipeline stages
  - **Orchard-SWE:** Coding agents; 107K trajectories distilled from MiniMax-M2.5 and Qwen3.5-397B; credit-assignment SFT from productive segments of unresolved trajectories; Balanced Adaptive Rollout for RL
  - **Orchard-GUI:** 4B vision-language computer-use agent; 0.4K distilled + 2.2K open-ended tasks
- **Results:** Starting from Qwen3-30B-A3B-Thinking → 64.3% SWE-bench Verified after SFT, 67.5% after SFT+RL (new SOTA for open-source of comparable size). Orchard-GUI: 74.1% WebVoyager, 67.0% Online-Mind2Web, 64.0% DeepShop
- **Key insight:** Credit-assignment SFT learns from unresolved trajectories (not just completed ones) — enables better agent training from imperfect data
- **Subjects:** cs.CL, cs.AI, cs.LG

### 2. MeMo: Memory as a Model
**arXiv:2605.15156** (May 14, 2026) — Arun Verma et al.
- **Problem:** LLMs are frozen after pretraining; real-world apps need timely domain-specific knowledge without costly retraining
- **Solution:** Encodes new knowledge into a dedicated memory model while keeping LLM parameters unchanged
- **Advantages:** (a) captures cross-document relationships, (b) robust to retrieval noise, (c) avoids catastrophic forgetting, (d) no access to LLM weights/logits needed (plug-and-play for closed-source), (e) retrieval cost independent of corpus size at inference
- **Results:** Strong performance on BrowseComp-Plus, NarrativeQA, MuSiQue benchmarks
- **Key insight:** Dedicated memory model approach enables domain knowledge integration without touching base model — compatible with any LLM API
- **Subjects:** cs.CL, cs.AI, cs.LG

### 3. Self-Recall Thinking (SRT): Multi-turn Dialogue Consistency
**arXiv:2605.15102** (May 14, 2026) — Renning Pang et al.
- **Problem:** Multi-turn dialogue systems struggle to track dependencies across non-adjacent turns; info becomes sparse in long conversations; processing entire history causes efficiency bottlenecks
- **Solution:** Three-stage framework — (1) Dependency Construction → self-recall chains, (2) Capability Initialization (training with recall tokens), (3) Reasoning Improvement (verifiable rewards)
- **Results:** +4.7% F1 score, -14.7% end-to-end latency vs prior methods; balances reasoning latency and accuracy
- **Key insight:** Endogenous reasoning process with interpretable recall steps — no external memory modules needed
- **Subjects:** cs.CL, cs.AI

### 4. AsyncFC: Future-based Asynchronous Function Calling for LLMs
**arXiv:2605.15077** (May 14, 2026) — Guangyu Feng et al.
- **Problem:** Function calling is constrained by synchronous execution — LLM decoding blocked until each function completes, causing latency bottlenecks
- **Solution:** Pure execution-layer framework decoupling LLM decoding from function execution; enables overlap between decoding and execution, plus inter-function parallelism
- **Key finding:** LLMs have native capability to reason over symbolic futures representing unresolved execution results — enables asynchronous paradigm for model-tool interaction without model changes or fine-tuning
- **Results:** Significantly reduces end-to-end task completion time while preserving accuracy across standard function-calling and software engineering benchmarks
- **Key insight:** Asynchronous function calling is a pure infrastructure win — no model modification needed, exploits native capability over symbolic futures
- **Subjects:** cs.CL, cs.AI, cs.LG

### 5. Preventive Consultation via Probabilistic Chain-of-Thought Completion (COTCAgent)
**arXiv:2605.15016** (May 14, 2026) — Chuanzhi Xu et al.
- **Problem:** LLMs hallucinate clinical trends/metrics when quantitative evidence is textually implied; non-uniform EHR time series and scarce labels hinder long-range temporal dependency capture
- **Solution:** Three-module hierarchical framework — (1) Temporal-Statistics Adapter (TSA): converts analytical plans to executable code, (2) Chain-of-Thought Completion layer with symptom-trend-disease knowledge base + weighted scoring, (3) Bounded completion module via standardized inquiries and iterative scoring
- **Results:** 90.47% Top-1 accuracy on self-built dataset; 70.41% on HealthBench — outperforms medical agents and mainstream LLMs; powered by Baichuan-M2
- **Key insight:** Decoupling statistical computation, feature matching, and language generation eliminates reliance on complex multimodal inputs
- **Subjects:** cs.CL, cs.AI

### 6. Quantifying and Mitigating Premature Closure in Frontier LLMs
**arXiv:2605.15000** (May 14, 2026) — Rebecca Handler et al.
- **Problem:** Premature closure (committing to conclusion before sufficient info) is a known diagnostic error contributor — underexamined in LLMs
- **Definition:** Inappropriate commitment under uncertainty: providing answer/recommendation when safer response would be clarification, abstention, escalation, or refusal
- **Findings:** False-action rates of 55-81% (MedQA) and 53-82% (AfriMed-QA) when correct choice removed; 30% inappropriate answers on 861 HealthBench questions; 78% on 191 physician-authored adversarial queries
- **Mitigation:** Safety-oriented prompting reduces premature closure but residual failure persists
- **Key insight:** Medical LLMs need to evaluate whether they know when NOT to answer — current models don't know when to abstain
- **Subjects:** cs.CL, cs.AI

### 7. The Scientific Contribution Graph: Automated Literature-based Technological Roadmapping
**arXiv:2605.15011** (May 14, 2026) — Peter Jansen et al.
- **Resource:** 2 million detailed scientific contributions from 230K open-access papers, connected by 12.5 million prerequisite edges (AI/NLP domain)
- **Task:** Scientific prerequisite prediction — predict which existing technologies enable future discoveries
- **Results:** Contemporary models reaching 0.48 MAP with temporally filtered backtesting — rapidly improving
- **Key insight:** Large-scale extraction of scientific contribution structure enables automated tech roadmapping and discovery
- **Subjects:** cs.CL

### 8. ML-Embed: Inclusive and Efficient Multilingual Embeddings (ICML 2026)
**arXiv:2605.15081** (May 14, 2026) — Ziyin Zhang et al.
- **Problem:** Three barriers: prohibitive computational costs, narrow linguistic focus neglecting most languages, lack of transparency from closed-source models
- **Solution:** 3-Dimensional Matryoshka Learning (3D-ML) — MEL for parameter efficiency, MLL for flexible inference-time depth, MRL for storage
- **Scale:** 140M to 8B parameters, massively multilingual dataset; all models/data/code released
- **Results:** Sets new records on 9/17 MTEB benchmarks, especially strong on low-resource languages
- **Key insight:** 3D approach (storage + inference + parameter efficiency) needed for globally equitable and computationally efficient embedding models
- **Subjects:** cs.CL, cs.AI

### 9. PPOW: Performance-Driven Policy Optimization for Speculative Decoding
**arXiv:2605.14978** (May 14, 2026) — Jie Jiang et al.
- **Problem:** Speculative decoding bottlenecked by hard-to-draft positions where early mismatch truncates accepted prefix; learning-based drafters still use token-level objectives despite speculative utility being window-level
- **Solution:** RL framework shifting from token-level imitation to window-level optimization with Cost-Aware Speedup Reward, Distribution-Based Proximity Reward, Adaptive Divergence-Aware Windowing
- **Results:** Average acceptance length 6.29-6.52, speedups 3.39-4.36x across model families and benchmarks under unified decoding protocol
- **Key insight:** Window-level optimization is practical for improving speculative decoding efficiency — performance-driven approach beats token-level imitation
- **Subjects:** cs.CL

### 10. AI Knows When It's Being Watched: Strategic Action and Contextual Register Modulation
**arXiv:2605.15034** (May 14, 2026) — Vinicius Covas Alves et al.
- **Study:** 100 multi-agent debate sessions across 5 conditions; draws on Habermas, Goffman, Bell, Hawthorne Effect
- **Findings:** Monitored conditions show +24.9% and +24.2% TTR change; automated AI monitoring yields +22.2%; audience-framing yields +17.7% (F=2.79, p=.031); message length shows fully dissociated effect (F=4.95, p<.001)
- **Key insight:** LLMs are sensitive to observer identity — human evaluation elicits stronger register formalization than automated AI surveillance
- **Implications:** For AI governance and algorithmic auditing — context matters
- **Subjects:** cs.CL, cs.AI, cs.CY, cs.MA

### 11. GranuRAG: Multi-Granularity Evidence Retrieval for Verifiable Multimodal RAG
**arXiv:2605.15019** (May 14, 2026) — Guanhua Chen et al.
- **Problem:** Multimodal RAG retrieves at coarse granularities (entire images/scenes) — mismatch with fine-grained user queries; failures unverifiable
- **Solution:** GranuRAG treats visual elements as first-class retrieval units; three stages: element-level detection/classification, multi-granularity cross-modal alignment, attribution-constrained generation
- **Benchmark:** GranuVistaVQA with real-world landmarks, element-level annotations, partial observation challenge
- **Results:** Up to 29.2% improvement over six strong baselines; enables transparent error diagnosis
- **Key insight:** Element-level grounding enables verifiable retrieval — each failure is traceable to specific visual element
- **Subjects:** cs.CL

### 12. Chain-of-Procedure: Hierarchical Visual-Language Reasoning for Procedural QA
**arXiv:2605.14928** (May 14, 2026) — Guanhua Chen et al.
- **Task:** Visual procedure question answering (VP-QA) — users query next-step actions via images of intermediate states
- **Benchmark:** ProcedureVQA — identifies two critical VLM limitations: inadequate cross-modal retrieval of structured procedures and misalignment between image granularity and text step decomposition
- **Solution:** CoP framework — retrieves relevant instructions using visual cues, performs step refinement through semantic decomposition, generates next step
- **Results:** Up to 13% absolute improvement over standard baselines across six VLMs
- **Key insight:** Procedural reasoning requires explicit hierarchical decomposition matching visual state granularity to textual step structure
- **Subjects:** cs.CL

## Task 2: Reasoning, Efficiency & Architecture Papers

### 13. OpenDeepThink: Parallel Reasoning via Bradley-Terry Aggregation
**arXiv:2605.15177** (May 14, 2026) — Shang Zhou et al.
- **Problem:** Test-time compute scaling via breadth (parallel sampling) hits selection bottleneck — no ground-truth verifier, pointwise LLM judging is noisy and biased
- **Solution:** Pairwise Bradley-Terry comparison for candidate selection; LLM judges random pairs, aggregates votes into global ranking; top candidates preserved, top 75% mutated using natural-language critiques; bottom 25% discarded
- **Results:** Raises Gemini 3.1 Pro's Codeforces Elo by +405 points in 8 sequential LLM-call rounds (~27 min wall-clock); transfers across weaker/stronger models without retuning
- **Key finding:** Gains concentrated in objectively verifiable domains, reverse in subjective ones — BT aggregation works best where ground truth exists
- **Note:** Also releasing CF-73 (73 expert-rated Codeforces problems with International Grandmaster annotation)
- **Subjects:** cs.AI

### 14. FutureSim: Replaying World Events to Evaluate Adaptive Agents
**arXiv:2605.15188** (May 14, 2026) — Shashwat Goel et al.
- **Task:** Agents predict world events beyond knowledge cutoff while interacting with chronological replay of real news articles resolving over Jan–Mar 2026
- **Findings:** Clear capability separation; best agent accuracy 25%; many have worse Brier skill score than making no prediction at all
- **Key insight:** Current frontier agents still struggle with long-horizon open-ended adaptation in real-world settings; world-event prediction as evaluation benchmark reveals fundamental limitations
- **Subjects:** cs.LG, cs.AI, cs.CL

### 15. Shodh-MoE: Sparse MoE Routing for Multi-Physics Foundation Models
**arXiv:2605.15179** (May 14, 2026)
- **Problem:** Multi-physics SciML (fluid dynamics + porous media flows) causes gradient conflict, unstable optimization, plasticity loss in dense neural operators
- **Solution:** Sparse-activated latent transformer with physics-informed autoencoder (16^3 physical latents, Helmholtz-style velocity parameterization); Top-1 soft-semantic router assigns latent patches to expert subnetworks
- **Results:** Autonomous domain bifurcation: open-channel → Expert 0, porous-media → Expert 1; exact mass conservation (divergence ~2.8×10^-10); convergent simultaneous multi-regime training
- **Key insight:** Sparse expert routing mitigates multi-physics interference in universal neural operators
- **Subjects:** cs.LG, cs.AI, physics.comp-ph

### 16. MANSU: Quantization-Permanent Unlearning via Circuit Attribution
**arXiv:2605.15138** (May 14, 2026)
- **Problem:** 4-bit PTQ can reverse machine unlearning — gradient-based methods that achieve forgetting lose it under compression; methods surviving quantization barely change model
- **Root cause:** Per-parameter updates lie 47-828x below NF4 quantization bin width; sparsity-permanence tradeoff
- **Solution:** Causal circuit attribution to isolate minimal forget-set subgraph, circuit-restricted null-space projection with diagonal-Fisher retain bound, per-parameter magnitude floor guaranteeing quantization survival
- **Results:** First method to jointly satisfy all 4 properties (meaningful forgetting, retain preservation, non-positive PTQ gap, structural erasure)
- **Key insight:** Sparsity-permanence tradeoff explains why standard unlearning fails under quantization — circuit-level interventions needed
- **Subjects:** cs.LG, cs.CL, cs.ET

### 17. Behavioural Assurance Cannot Verify Safety Claims Governance Now Demands
**arXiv:2605.15164** (May 14, 2026) — Pratinav Seth et al.
- **Argument:** Behavioural assurance (evaluations and red-teaming) cannot verify latent representations or long-horizon agentic behaviours that governance frameworks presume to regulate
- **Concepts:** Audit gap (required vs achievable verification access), fragile assurance (evidential structure doesn't support asserted safety claim)
- **Finding:** 21-instrument inventory reveals incentive gradient where geopolitical/industrial pressures reward surface-level behavioral proxies over deep structural verification
- **Proposal:** Bound weight of behavioral evidence in legal text; extend pre-deployment access with mechanistic evidence classes (linear probes, activation patching, before/after-training comparisons)
- **Key insight:** Epistemological gap between what governance demands and what behavioural evaluation can provide — structural/mechanistic evidence needed
- **Subjects:** cs.LG, cs.AI

### 18. Case-Based Calibration of Adaptive Reasoning and Execution (CAST)
**arXiv:2605.15041** (May 14, 2026) — Renning Pang et al.
- **Problem:** Reliable tool use requires balancing reasoning depth with structural validity; existing methods fail on schema-faithful execution
- **Solution:** Case-driven framework treating historical execution trajectories as structured cases; CAST extracts case-derived signals for complexity profiling and failure mapping; fine-grained reward + adaptive reasoning via RL
- **Results:** Up to 5.85 pp gain in overall execution accuracy, 26% reduction in average reasoning length on BFCLv2 and ToolBench
- **Key insight:** Historical execution cases provide reusable adaptation knowledge for calibrated tool use
- **Subjects:** cs.AI, cs.CL

### 19. Streaming Speech-to-Text Translation with a SpeechLLM
**arXiv:2605.14766** (May 14, 2026) — Rogier van Dalen et al.
- **Problem:** Existing SpeechLLM systems wait for complete utterance or output at fixed intervals — not real streaming; cascade systems suffer from error propagation
- **Solution:** LLM learns to decide whether it has seen enough audio to output; trained with automatic alignments of input speech and output text
- **Results:** Translation quality close to non-streaming baseline with only 1-2 second latency across language pairs
- **Key insight:** Streaming requires the model to learn when to emit output, not just what to emit
- **Subjects:** cs.CL, cs.AI, eess.AS

### 20. Tokenizer Fertility and Zero-Shot Performance on Ukrainian Legal Text
**arXiv:2605.14890** (May 14, 2026) — Volodymyr Ovcharov et al.
- **Benchmark:** Seven models on 273 validated Ukrainian court decisions; three tasks
- **Findings:** (1) Tokenizer fertility varies 1.6x — Qwen3 models use 60% more tokens than Llama on identical input, directly affecting API cost; (2) NVIDIA Nemotron Super 3 (120B) achieves highest composite (83.1), outperforming Mistral Large 3 (675B total, 41B active) at 1/3 the API cost; (3) Few-shot prompting degrades performance by up to 26 pp for morphologically rich languages
- **Key insight:** Tokenizer analysis should precede model selection for non-English languages; zero-shot more reliable default than few-shot for morphologically rich languages
- **Subjects:** cs.CL
