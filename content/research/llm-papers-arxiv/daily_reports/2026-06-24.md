## 🔬 arXiv Papers (June 24)

### FMLM+: Posterior Refinement for Fast Language Generation via Any-Order Flow Maps
**arXiv:2606.24773** | Generation Efficiency | cs.CL

Non-autoregressive generation (NAR) models allow iterative refinement but existing approaches fail to realize their potential: Masked Diffusion Models (MDMs) suffer from factorization error causing quality collapse; Flow Map Language Models (FMLMs) achieve excellent few-step generation but sacrifice inference-time flexibility.

FMLM+ bridges the gap by equipping FMLMs with masking-style noise schedules. While generating the full sequence in a single step, FMLM+ simultaneously scores the global consistency of each token a posteriori. Posterior Refinement enables the model to adaptively self-correct outputs, matching discrete baseline quality with 32x fewer NFEs.

Across diverse benchmarks, FMLM+ with Posterior Refinement improves the speed-quality tradeoff over both MDM and FMLM families, providing a scalable foundation for high-fidelity language modeling.

**Key insight:** Posterior scoring — evaluating each token's global consistency after the fact — is the missing ingredient that lets flow-based models self-correct without sacrificing the parallel-generation advantage. 32x fewer NFEs is a massive efficiency win.

🔗 https://arxiv.org/abs/2606.24773

### DREAM: Dense Retrieval Embeddings via Autoregressive Modeling
**arXiv:2606.24667** | Dense Retrieval | cs.CL

Standard dense retrievers are trained with contrastive objectives requiring labeled positive/negative pairs — costly and hard to obtain at scale. DREAM investigates whether an LLM's autoregressive next-token prediction objective can supervise dense retrieval.

Intuition: if a document is relevant to a query, conditioning on that document should make the target output easier for the LLM to predict. A key challenge: next-token prediction loss is computed inside the LLM while the retriever is a separate embedding model. Solution: inject retriever-generated query-document similarity scores into selected attention heads of a frozen LLM. During training, these scores determine how much attention each candidate document receives while the LLM predicts the target output. The resulting prediction loss provides gradients for retriever training through the attention mechanism.

Evaluated on BEIR and RTEB with embedding backbones from 0.5B to 3B parameters. DREAM consistently outperforms existing baselines across different model scales.

**Key insight:** Autoregressive language modeling provides a rich supervision signal for dense retrieval without requiring explicit labeled pairs — the next-token prediction process itself contains information about document relevance.

🔗 https://arxiv.org/abs/2606.24667

### SHERLOC: Structured Diagnostic Localization for Code Repair Agents
**arXiv:2606.24820** | Agents/Code | cs.CL

LLM agents solving repository-level coding tasks waste ~50% of their budget on locating faults before editing. Dedicated localization frameworks have emerged but are still evaluated as file retrieval rather than actionable diagnosis.

SHERLOC (Structured Hypothesis-driven Exploration and Reasoning for Localization): training-free framework pairing a reasoning LLM with compact repository tools and self-recovery, without fine-tuning or multi-agent orchestration.

Results: 84.33% accuracy@1 on SWE-Bench Lite, 81.27% recall@1 on SWE-Bench Verified. At ~30B parameters, matches or outperforms other agentic methods. Injecting SHERLOC locations and diagnostic findings into repair agents yields +5.95 pp resolve rate on SWE-Bench Verified while cutting localization tokens by 36.7% and total tokens by 23.1%.

**Key insight:** Localization should produce actionable diagnosis, not just file names. SHERLOC's structured reasoning over compact repository context (not full codebase) is what makes it token-efficient — halving localization cost while improving downstream repair.

🔗 https://arxiv.org/abs/2606.24820

### Are We Ready for an Agent-Native Memory System? — Systematic Evaluation
**arXiv:2606.24775** | Agents/Memory | cs.CL, cs.DB, cs.IR

Memory for LLM agents has evolved from simple retrieval-augmented mechanisms into systems supporting persistent storage, extraction, retrieval/routing, and dynamic lifecycle governance. Yet existing evaluations still benchmark agent memory through end-to-end task success metrics, treating the underlying system as a monolithic black box. Critical concerns — operational costs, architectural trade-offs, robustness under dynamic knowledge updates — remain unexplored.

This paper presents a systematic experimental study decomposing agent memory into four core modules: (1) representation and storage, (2) extraction, (3) retrieval and routing, (4) maintenance. Evaluates 12 representative memory systems across five benchmark workloads spanning 11 datasets.

Key findings: No single architecture dominates across all scenarios — effectiveness depends heavily on how well the memory structure aligns with the workload bottleneck. Localized maintenance is more cost-efficient than global reorganization. Fine-grained ablation quantifies individual effects on representation fidelity, retrieval precision, update correctness, and long-horizon stability.

**Key insight:** Agent memory is a data management problem, not just a retrieval problem. The field needs to decompose memory systems into tractable modules and evaluate each separately — monolithic end-to-end metrics hide what's actually working or failing.

🔗 https://arxiv.org/abs/2606.24775

### Other Notable Papers

**Claim-Anchored Attribution for Multi-Document Summarization / CAMS (2606.23989)**
cs.CL | Hallucination Reduction | Proposes Extract-Select-Rewrite paradigm where attribution unit is the atomic claim, not the passage. Claims are extracted with token-level provenance, clustered across documents (flagging inter-source conflicts), then selected support-aware before rewriting. Lifts multi-source attribution accuracy by ~two-thirds vs end-to-end baselines. Every summary sentence is anchored to a support-checked claim.

**Quality-Aware Training Data Selection for Scientific Summarization (2606.24828)**
cs.CL | Data Efficiency | Constructs 1.88M PMC article dataset for biomedical/life-science summarization. Shows author-written abstracts vary in alignment with source articles — quality signals can guide training data selection. Training on high-quality subsets outperforms random sampling at matched sizes. Factuality-oriented metrics particularly benefit.

**Natural Identifiers for Privacy Auditing in LLMs (2606.24408)**
cs.LG | Privacy | ICLR 2026 | NIDs: structured random strings (cryptographic hashes, shortened URLs) naturally occurring in training data. Enable post-hoc differential privacy auditing without retraining and dataset inference without private held-out datasets. Format allows generating unlimited additional NIDs from the same distribution.

**Data Augmentation via Fourier Analysis (2606.24418)**
cs.LG | Theory | COLT 2026 | 42-page theoretical study of partial vs full data augmentation via representation theory of finite groups. Partial augmentation (random subset of group elements) achieves same minimax rates as full augmentation up to approximation error. Enforcing exact invariance via augmentation requires averaging over the full group — no strict subset suffices for sufficiently expressive hypothesis spaces.

## 🧠 Reasoning Theory: CoT Is Not Chain-of-Thought

### "LLM Reasoning Is Latent, Not Chain of Thought" (arXiv:2604.15726)
**Position Paper** | Reasoning Theory

This paper argues that LLM reasoning should be studied as latent-state trajectory formation rather than faithful chain-of-thought. Chain-of-thought explanations systematically misrepresent the true reason for a model's output — they are post-hoc rationalizations, not the actual reasoning process.

Why this matters: Claims about faithfulness, interpretability, benchmark validity, and inference-time intervention all depend on what the field takes the primary object of reasoning to be. If CoT is merely a textual artifact of the model's latent reasoning process (not the process itself), then:
- Chain-of-thought faithfulness research is studying the wrong object
- CoT-based benchmarks may not measure what they claim
- Interventions targeting CoT may not affect actual reasoning

This aligns with earlier observations (ASAG, June 19) that reasoning models can overthink — producing more tokens without better answers. If the real reasoning is latent, the textual chain is a performance, not a trace.

**Key insight:** The field may be conflating the output of reasoning (a generated text stream) with the reasoning process itself. Treating latent state dynamics as the primary object of study reframes how we should evaluate, interpret, and intervene on LLM reasoning.

🔗 https://arxiv.org/abs/2604.15726

## 🔍 Key Pattern: Reasoning Is Inhabited, Not Traced

Two distinct threads today converge on the same theme: **chain-of-thought is performance, not proof**. The position paper (2604.15726) argues reasoning is latent-state formation — CoT is post-hoc narrative, not the mechanism. SHERLOC's results support this indirectly: better localization (diagnosis) improves repair even though the "reasoning" about where the bug is happens in latent space, not in the textual chain. Meanwhile, FMLM+ shows that adaptive self-correction via posterior scoring works better than explicit iterative refinement strategies. The common thread: models reason in latent space and generate approximate textual justifications — treating CoT as ground truth leads to misguided evaluation and intervention strategies.
