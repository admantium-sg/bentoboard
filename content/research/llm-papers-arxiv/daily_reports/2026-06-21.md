## 🔬 Efficiency / Quantization

### UltraQuant: 4-bit KV Caching for Context-Heavy Agents (2606.20474)
**Efficiency** | KV-cache quantization | AMD GPU support

Key insight: Tail tokens (last 20% of context) dominate KV-cache memory — UltraQuant exploits this with per-tensor 4-bit quantization for the tail segment while keeping head tokens in FP16.

- **3.47× P50 TTFT speedup** over FP8 baseline on context-heavy agentic tasks
- **1.63× output throughput** improvement
- Custom quantization kernels for AMD GPUs (not just NVIDIA)
- Differentiates from prior work (KIV, QoQ) by targeting the distributional skew in KV caches rather than uniform bit-width

**Why it matters:** Agentic workflows with long context windows (RAG, multi-turn对话) spend significant compute on re-attending to cached tokens. UltraQuant's tail-aware approach is a pragmatic recognition that not all cached content is equally important.

🔗 https://arxiv.org/abs/2606.20474

### UFP4: Uniform FP4 Training Recipe (2606.20381)
**Quantization** | LLM pretraining | E1M2 vs E2M1

Key insight: Non-uniform FP4 formats (E2M1) suffer from "Shrinkage Bias" — systematic negative rounding error from geometric asymmetry of representable bins. Uniform grids (E1M2/INT4) avoid this.

- Identifies Shrinkage Bias as the root cause of E2M1 training instability
- RHT (Random Hadamard Transform) amplifies this bias multiplicatively across layers
- Proposes UFP4: uniform 4-bit training recipe applying RHT to all three training GEMMs
- Results on Dense 1.5B, MoE 7.9B, MoE 124B long-run pretraining
- Argues hardware accelerators should support E1M2/INT4 as first-class training primitives

**Why it matters:** As FP4 training hardware (Blackwell, Rubin, AMD MI350) becomes mainstream, the E2M1 vs E1M2 choice will directly impact training stability. This provides both the theoretical diagnosis and a practical recipe.

🔗 https://arxiv.org/abs/2606.20381

## ⚡ Inference / Systems

### FlashRT: Execution-State Capsules for Sub-Millisecond KV- Cache Checkpoint/Restore (2606.20537)
**Systems** | KV-cache | Checkpoint-restore | GPU snapshot

Key insight: KV caches are "execution-state capsules" — compressed checkpoint representations of LLM forward pass state. The system exploits the graph-bound property of LLM inference to enable ultra-fast snapshot/restore.

- **Sub-millisecond GPU snapshot** (vs seconds/minutes for CPU-based approaches)
- **27× TTFT speedup** at 16k tokens vs recomputation
- Captures KV-cache state, recurrent hidden states, convolution state, and multi-token prediction (MTP) state
- For speculative decoding / preemption scenarios

**Why it matters:** Long-context inference with frequent context switching (multi-agent workflows, tool-calling chains) has traditionally paid an enormous latency cost to restore KV state. FlashRT's approach makes near-instantaneous context switching practical.

🔗 https://arxiv.org/abs/2606.20537

## 🧠 Memory / Agent Self-Evolution

### MAA: Marginal Advantage Accumulation for Memory-Driven Agent Self-Evolution (2606.20475)
**Agents** | Memory | Self-evolution | Token efficiency

Key insight: Agents that accumulate evidence across batches (using stored episodic memory) can self-evolve their strategies without expensive per-batch feedback. MAA uses a "marginal advantage" estimator to weight recent experiences by their unexpectedness.

- **Best in 14/16** benchmark settings vs prior art (Self-Refine, Self-Correct, EA等)
- **75% token reduction** vs comparison-based methods
- Cross-batch evidence accumulation distinguishes helpful from misleading corrections
- Lightweight episodic memory with sliding window

**Why it matters:** The core tension in agent self-improvement is feedback cost. MAA demonstrates that a principled statistical estimator (marginal advantage) can replace expensive comparison-based feedback, enabling self-evolution at scale.

🔗 https://arxiv.org/abs/2606.20475

## 🎯 Alignment / Feedback

### IFLLM: Implicit Feedback from Mouse/Eye Gaze for LLM Alignment (2606.20482)
**Alignment** | Implicit feedback | DPO | User behavior

Key insight: Users reveal preference through behavioral signals (mouse trajectories, eye gaze) even when not providing explicit feedback. These implicit signals can train reward models that outperform text-only approaches.

- Dataset: 1336 multi-turn questions, mouse trajectories + eye gaze from 59 MTurk workers
- Reward model using implicit feedback: **DPO accuracy 55% → 64%** vs text-only
- **~3× relative response quality improvements** after DPO across 8 LLMs
- Diverse gaze/mouse behavior patterns across users

**Why it matters:** High-quality explicit preference data is expensive and sparse. This work shows that the implicit behavioral signal that's worth billions to internet companies is also directly applicable to LLM alignment — and the improvement is substantial.

🔗 https://arxiv.org/abs/2606.20482

## 🔍 Reasoning / Transparency

### DiffusionGemma: Mechanistic Transparency of Diffusion Reasoning Models (2606.20560)
**Reasoning** | Diffusion models | Interpretability | Mechanistic

Key insight: Gemma-based diffusion reasoning models (outputting tokens in noised→denoised order) show evidence of non-chronological reasoning — the model processes information in a purposeful order that doesn't match the final output sequence.

- #1 trending paper on papers.cool cs.LG (June 18–19)
- Mechanistic interpretability study of how diffusion enables multi-step reasoning
- Finds evidence that intermediate steps in the denoising process correspond to reasoning sub-goals
- Relates to broader "chain-of-thought via diffusion" direction

**Why it matters:** The diffusion-vs-autoregressive debate for reasoning is increasingly实证. DiffusionGemma adds mechanistic evidence that the non-linear token generation order may actually be a feature (enabling "parallel" reasoning) rather than a bug.

🔗 https://arxiv.org/abs/2606.20560

## 🌐 Multi-Agent / Evaluation

### Contagion Networks: Evaluator Bias Propagation in Multi-Agent LLM Evaluation (2606.20493)
**Multi-agent** | Evaluation | Bias | Contagion dynamics

Key insight: When multiple LLMs evaluate each other's outputs, evaluator biases don't just persist — they *amplify* through the network. The paper models this as a contagion process over evaluation graphs.

- Evaluator agreement vs ground-truth accuracy can diverge substantially
- **72.4% reduction in effective contagion** with k=3 diverse evaluators vs k=1
- Evaluator bias is not mean-centered — systematic biases in one direction propagate asymmetrically
- Diversity in evaluators (different capability profiles) is more important than raw capability

**Why it matters:** Multi-agent evaluation (where LLMs judge LLMs) is increasingly used in practice. This work provides both a formal model for understanding evaluator bias and a practical mitigation strategy.

🔗 https://arxiv.org/abs/2606.20493

## 🛠️ RAG / Tool Use

### Tool-Intent Stabilization in Streaming RAG (2606.20113)
**RAG** | Tool use | Latency | Streaming

Key insight: 73.9% of queries admit "substantial latency hiding" — the opportunity to launch tool queries in parallel with continued context processing before the LLM has explicitly decided to call tools.

- Streaming RAG with parallel tool query execution
- Distinguishes "intent-known" (model explicitly calls tool) from "intent-anticipated" (system pre-launches tool based on context)
- Reduces end-to-end latency by overlapping retrieval with generation

**Why it matters:** RAG latency is often measured as retrieval time, but the real bottleneck is the wait for the LLM to "decide" to retrieve. This work makes the case that anticipatory tool execution is both feasible and significant.

🔗 https://arxiv.org/abs/2606.20113

### Train/Retrieve/Both: Ontario RTA Statutory Citation (2606.20359)
**RAG** | Legal** | Fine-tuning | Hybrid

Key insight: Four-arm comparison (fine-tuning only, retrieval only, hybrid, both) on real-world legal statutory citation shows that retrieval remains critical even with fine-tuned models.

- Domain: Ontario Residential Tenancies Act statutory reasoning
- Hybrid approaches outperform single-strategy approaches
- Fine-tuning alone doesn't capture up-to-date legal knowledge
- Retrieval alone struggles with legal reasoning patterns

**Why it matters:** Practical demonstration that the "just fine-tune" vs "just RAG" debate is a false dichotomy — the legal domain (high-stakes, dynamic, complex) particularly benefits from hybrid approaches.

🔗 https://arxiv.org/abs/2606.20359

## 📊 Benchmarks / Evaluation

### REDACT: Multilingual PII Detection Benchmark (2606.19881)
**Benchmarks** | PII detection | Multilingual | GDPR

Key insight: Aggregate F1 masks systematic failure structure in PII detectors. REDACT provides 13,427 records, 324,078 entity annotations, 51 entity types, 25 languages, with controlled generation across 9 axes.

- Strength-2 covering array controls: domain, format, difficulty, length, density, code-switching, language, adjacency, co-occurrence
- Rule-based detectors (Presidio) fail badly on HIGH-sensitivity categories (recall 0.07)
- LLM detectors (GPT-4.1, Claude Sonnet 4.6) more robust but still struggle with sensitivity-tier assignment
- Sensitivity-tier assignment is the hardest axis

**Why it matters:** For practical PII detection in production, aggregate metrics give false confidence. The stratified evaluation reveals that the highest-stakes cases (HIGH sensitivity, non-verbatim disclosure) are exactly where rule-based systems fail most.

🔗 https://arxiv.org/abs/2606.19881
