## Verification, certificates and proof systems

**2611.34132** Agent-as-a-Verifier: From Scores to Evidence for General Verification — Replaces scalar discriminative reward models with an agentic, certificate-producing verification system: role-separated LLM agents run a formal-methods-inspired claim-obligation-certificate protocol, extracting a **verdict-blind dependency graph of claims** and verifying each independently. The paper's argument is that score-based verifiers give no auditable evidentiary basis for a judgment, and that existing generative process reward models fail to exploit agentic capability (tool use, iterative reasoning) needed for fact-checking and fine-grained claim verification. Positions verification for test-time scaling, recursive intelligence and automated research, where feedback drives optimisation.
Source: https://arxiv.org/abs/2611.34132

**2611.33741** FlashProve-Next: Verifiable Inference for Production LLM APIs — Lets clients of closed-weight APIs verify that a provider actually ran the advertised model, precision, hidden prompt and reasoning budget, without modifying native serving (bf16/fp8/mxfp4, random sampling, FlashAttention, CUDA graphs, batching, prefix caching) and without disclosing weights, prompts, hidden reasoning or activations. Uses a non-depleting Reed–Solomon weight commitment (`model_id`) opened inside proofs via hidden column openings, plus local per-operator rounding contracts that remove integer surrogates and the refusal-bit leak. Cost-weighted spot-checking supports non-interactive public verification (NI-315, ε ≤ 2⁻⁴⁰, Q ≤ 2⁶⁴) and external-seed C_pre mode (ExtSeed-153, ε ≤ 2⁻²⁰).
Source: https://arxiv.org/abs/2611.33741

**2611.33676** Interactive Proofs as a Unified Framework for Evaluating and Leveraging Verifiable Proof Generation by LLM Agents — Introduces **Merlin-Bench**, borrowing interactive proof systems from complexity theory: the LLM agent is cast as the *prover*, interacting with a formal verifier to substantiate a claimed answer under a designated protocol. The point is to measure protocol-agnostic proof construction rather than proficiency with any one proof language or tool. 100 cases across 15 problem families, built by an automated test-case construction framework; 10 frontier LLMs across multiple agent harnesses. Finding: reliably producing verifiable proofs in accordance with specified protocols "remains a substantial challenge."
Source: https://arxiv.org/abs/2611.33676

**2611.33078** FOL-Proof: Verifying LLM Text-to-Logic Translations via Deterministic Semantics — A "semantic firewall" for the increasingly common pipeline of LLM → first-order logic: deterministically derives a pool of candidate readings via the English Resource Grammar and Minimal Recursion Semantics, then uses an SMT solver to check logical equivalence with the LLM's formula. Faithful → accept, unfaithful → reject or optionally repair by repeated LLM invocation. Deliberately conservative: incomplete search, unsupported constructions or inconclusive checks yield **abstention rather than false rejection**.
Source: https://arxiv.org/abs/2611.33078

**2611.32931** Reading Decisions Before Spans: Efficient Generative Verification — A frozen 2B span verifier whose output chooses between an empty error list and its first object *before* producing any locations. "Native8" stops at that choice; "Prefill1" supplies the seven fixed syntax tokens preceding it and generates only the unrestricted branch token, keeping the native instruction. On 2,015 code-agent TEST responses, Prefill1 uses **84.84% less eager resident service** than full generation at released-reference F1 83.43 vs 83.41, and saves 31.98% over Native8 despite identical logical token totals; the saving persists at 6.74–26.73% under default compiled execution.
Source: https://arxiv.org/abs/2611.32931

**2611.33668** Verifiable but Not Predictable: What Sentence Embeddings Know About Propositional Decomposition — Separates two asymmetric questions on PropSegmEnt (English Wikipedia sentences segmented by three human annotators): *verification* (does this proposition belong to this sentence?) and *prediction* (how many propositions should this sentence yield?). An NLI judge verifies membership at **92.8% accuracy, AUC 0.977**; residual errors are mostly propositions true in document context rather than genuine entailment failures. Vector geometry cannot verify — cosine similarity saturates and a sentence embedding is not a linear combination of its propositions' embeddings. For prediction, every symbolic anchor tested (token count, CPIDR idea-density, Neo-Davidsonian predicate count) collapses into a length proxy.
Source: https://arxiv.org/abs/2611.33668

**2611.33031** Can a Frontier LLM Repair a Quantized Network by Tool-Free Weight-Space Programming? — Four Claude-family LLMs receive the complete weights of a 20k-parameter CIFAR-10 CNN **as text** and must produce a 4-bit network with no tools, no data, no ability to run inference. RTN to 4-bit drops test accuracy 81.4% → 60.4%. With one answer per layer, **Opus 5.5 raises the 4-bit network to 77.95%** by balancing rounding errors within each 3×3 kernel, reasoning over the integer weights without tools — 3.5 pp below the float network and 2.8 pp below AdaRound. Four protocols distinguish models told the accuracy dropped from models told only to quantize (testing spontaneous optimisation vs plain RTN).
Source: https://arxiv.org/abs/2611.33031

**2611.34612** Do We Really Need an LLM for Weight-Space Programming? — Argues that using LLMs to edit neural weights conflates LLM scripting with the algebra of forward-only editing. ## RL, credit assignment and reasoning structure

**2611.34746** BRIAR: Martingale Belief Smoothing on Bifurcation-Guided Reasoning Trees — Traces two RLVR pathologies (an early misstep derailing the rest of the trace; redundant verification after the answer is already determined) to one structural fact: under an on-policy verifier the true prefix pass probability V^π(u) along a reasoning trace forms a **[0,1]-bounded Doob martingale whose learnable credit variance is strictly conserved** and bounded by V^π(u)(1−V^π(u)), vanishing at both the derailed (V^π→0) and absorbed (V^π→1) boundaries. BRIAR is a tree-structured RLVR framework built on that geometry: it expands discourse-aligned reasoning trees along an upper-confidence outcome-bifurcation frontier, steering rollouts away from absorbed rumination.
Source: https://arxiv.org/abs/2611.34746

**2611.33648** PRIOR: Pre-Call Reasoning in SFT and Its Influence on Tool-Use Retention under RL — Tool use learned in SFT is not always retained under RL. Three SFT datasets with matched token budgets but different **tool-call depths** (Low/Medium/High) reach similar RL training accuracy yet show markedly different tool-use dynamics: tool initiation *increases* in Low, *declines* in Medium, and *collapses* in High. The datasets also differ in reasoning preceding each tool call — High trajectories contain considerably less pre-call reasoning, motivating the hypothesis that pre-call reasoning affects tool-use calibration and hence retention. An idealized theoretical analysis gives a selective-retention view: overall and tool-conditioned accuracy advantages survive outcome-only optimisation, while tool initiation does not.
Source: https://arxiv.org/abs/2611.33648

**2611.34777** When Every Rollout Fails: Splicing Learner-Conditioned Options into Long-Horizon Agent RL — Group-based RLVR on long-horizon agent tasks frequently yields **all-fail groups** (every trajectory zero reward), leaving group-relative methods with no reward-based policy gradient. The usual remedy — full solutions from a stronger model — is expensive and exposes the learner to long off-policy histories. **SPLICE** builds local training targets from failed *current-policy* trajectories online: a proposal model picks a splice point in a current-policy trajectory and generates several bounded options from it; each option's value is estimated via repeated current-policy continuations, positive estimates become a return-weighted local target, and the policy is fit on those options. Evaluated on SWE-bench Verified and BrowseComp-Plus across two policy families.
Source: https://arxiv.org/abs/2611.34777

**2611.34756** Collect for Coverage, Replay with Evidence: Adaptive and Efficient On-Policy Distillation for Long-Horizon Agents — Fully online on-policy distillation is costly for long-horizon agents because each update depends on fresh environment rollouts; prefix replay samples current-student responses from stored histories, cutting idle time for long-tail rollouts and letting each trajectory support multiple updates. The paper's analysis of the complete prefix-replay pipeline finds two limitations in long-horizon settings: in *collection*, teacher-only trajectories miss student-induced histories while broader history coverage can reduce teacher reliability; in *reuse*, fixed position-based schedules cannot identify critical decisions occurring at any trajectory depth. **CARE-OPD** (Collect for coverAge, Replay with Evidence) adds student-seeded teacher completions plus response-level confidence gating to expand coverage while filtering unreliable updates, and uses **hindsight replay allocation** driven by downstream execution evidence to select consequential turns. Across Software Engineering and Deep Research it beats online OPD and prior prefix-replay baselines; on SWE-bench Verified it raises task success to **59.5%** while cutting end-to-end training time **45%** and environment actions **44%** relative to asynchronous online OPD.
Source: https://arxiv.org/abs/2611.34756

**2611.34703** Maco-RL: Scaling Agent Capabilities with Mixed-Task Reinforcement Learning — Mixed-task RL trains one unified policy across domains, avoiding per-domain specialists and an extra distillation stage, but must stabilise mixed-task learning, allocate rollout compute and support continual domain expansion. Maco-RL uses a **quota-based scheduler for asynchronous rollouts across task domains** (balancing gradient contributions, mitigating off-policy effects) plus **Tri-Buffer Sampling (TBS)**, which allocates compute among samples of differing mastery to sustain frontier exploration without losing acquired capabilities. On five benchmarks it raises Qwen3.5-27B's overall score **43.6 → 54.2 → 60.1** with continual expansion, reaching the frontier.
Source: https://arxiv.org/abs/2611.34703

**2611.33827** FEAST: Fair and Efficient Adaptive Sampling for Task-Free On-Policy Learning — Language agents trained from self-generated experience must allocate a limited rollout budget across heterogeneous capabilities. FEAST formalises this as the **Quota-Efficiency Law (QEL)** — allocation history can change learning efficiency even under matched capability-specific exposure — and separates *opportunity allocation* from *compute allocation*, discovering capability clusters dynamically while preserving their learning histories and reserving budget for each.

## Architecture, depth and decoding

**2611.34923** Mixture-of-Loops Transformer — Looped Transformers gain expressivity by reusing shared layers across loops at an efficiency cost. **MoLA (Mixture-of-Loops Attention)** uses keys and values as memory for selective reuse across depths and loops. MoLT-R (loop residual) retains the residual stream and reads local KV across loops for expressivity; MoLT-KV (loop KV) restarts from embeddings and reads current-loop local KV with preceding-loop memory KV at earlier positions for efficiency — this eliminates same-position cross-loop dependence and, with loop forcing for parallel training, unlocks single-traversal Mixture-of-Loops decoding beyond the training loop horizon. **U-shaped MoLT** separates memory construction from prediction readout and skips unused decoder traversals without changing predictions.
Source: https://arxiv.org/abs/2611.34923

**2611.33896** Looped Models are Fast Multi-Token Predictors — Looped LMs adapt computation per token without rescaling parameters, which has been used for self-speculative decoding (shallow loops draft, deep loops verify — effective because drafting still uses full parameters). This paper shows shallow loops are also predictive of *several* future tokens, and exploits it with **Floodgates**: append a block of mask tokens as a suffix and learn via low-rank adaptation to draft those tokens in parallel. Across seven models, five benchmarks, varying batch sizes and greedy/sampled decoding, Floodgates is the fastest lossless decoding method in most cases, **up to 7.5× acceleration** — enabled by all-depth training of looped models.
Source: https://arxiv.org/abs/2611.33896

**2611.34821** LoopTitan: What Does Parameter Revisit Buy a Mixture-of-Experts? — A sceptical control study of looped-MoE claims. Recent looped MoE work reports substantial gains over standard MoE at matched budgets (parameters, FLOPs, KV cache), but conflates **parameter revisit** with other design choices. Using matched non-revisit controls, the paper finds **parameter revisit itself buys almost nothing**: at matched budgets the state-of-the-art looped recipe decomposes with revisit last, and a non-revisit control retains *all* the gain — most from network shape, the rest from residual scale. The paper proves this scale acts as a **lower learning rate on revisited layers** (under AdamW).
Source: https://arxiv.org/abs/2611.34821

**2611.34492** FlyingStart: Learned Cross-Token Warm Starts for Fixed-Point Decoding in Recurrent-Depth Language Models — Recurrent-depth LMs generate each token by iterating a shared block until the hidden state converges; inference methods decide when to stop, yet every token still starts from random noise and pays full convergence cost. The paper argues *where the iteration starts* is a second independent lever: a token's fixed point is predictable from the state at which the previous token stopped, after a learned change of coordinates. FlyingStart is a linear warm start fitted in closed form on the frozen model, costing under 5% of one loop; the exit criterion still certifies the same distance to the fixed point. **2611.34776** DFly2: Turbocharging Long-Context Speculative Decoding by Sharing the Target's Sparsity — Natively sparse targets (DeepSeek-V4, Hy4) already pick attention positions per query over a cache they keep anyway — but drafters keep their own context cache over the whole prompt or a sliding window, costing memory, prefill time, prefix-cache hits and decode concurrency. **2611.34092** Improving Tail-Augmented Speculative Drafting with Hidden State Mixing and Gradient Detach — MTP modules and EAGLE-style drafters suffer a training-inference mismatch: training supplies hidden states from the backbone or a single MTP step, whereas inference attends to a target prefix followed by a growing tail of recurrently generated MTP states. ## Quantization, precision and serving

**2611.32624** HiCal: Offline Calibration for Hierarchical Scale Encoding in Accurate HiF4 Quantization — Block floating-point quantization makes scale choice decisive for low-bit LLM inference. HiFloat4 uses a hierarchical scale encoding (global E6M2 scale plus two levels of binary scale extensions), whose conventional rounding rule and fixed extension thresholds may not match the statistical characteristics of real tensors. HiCal is an **offline** calibration that refines encoding decisions at all three scale levels: a calibrated rounding bias for the Level-1 E6M2 scale and optimised scale-extension thresholds at Levels 2 and 3 based on empirical distributions of local group magnitudes. Parameters are fixed at inference while the hierarchical encoding still adapts per block.
Source: https://arxiv.org/abs/2611.32624

**2611.31737** GreenDynaMix: Thermal-Aware Dynamic Mixed-Precision MoE LLM Inference Systems — Sustained LLM inference generates heat that exacerbates silicon aging and reduces GPU reliability; keeping temperature in a safe range requires real-time frequency scaling, which costs throughput or accuracy. **2611.33542** RankCast: Phase-Aware Rank Balancing in MoE Serving — In disaggregated prefill/decode serving with Expert Parallelism, each layer waits for the busiest EP rank. RankCast is a unified system reducing rank-level maximum token counts in prefill and active-expert counts in decode: for every token it preserves the predicted Top-p experts and picks the remaining k−p from Top-L candidates (L > k).

**2611.34278** Latent-in-the-Middle: On the Security of Cross-Model Latent Communication in Multi-Agent Systems — Latent communication (sharing internal representations rather than natural-language messages) cuts communication overhead and prefill computation; cross-model **KV-cache transfer** uses a learned mapper to translate a source model's KV cache into one the target can use. But the target then consumes context it did not encode itself, so its safety alignment may not hold. The **Chasm** framework characterises cross-model handoff attacks across three new surfaces — source model, mapper, and the handoff mechanism itself. Finding: latent handoffs substantially undermine safety alignment and prompt-injection defences; a target model that follows only **0.4% of benchmark prompt injections naively**…
Source: https://arxiv.org/abs/2611.34278

**2611.34934** Attack Policy Selection can Mislead Monitor Evaluators — AI monitors (classifiers flagging dangerous agent behaviour) are evaluated against transcripts generated by *attack policies* standing in for dangerous deployment behaviour. Evaluating an ex-production OpenAI monitor, the measured **false negative rate is highly sensitive both to the method used to generate attack policies and to the optimisation level within that method**: 0.5%–20.8% across optimisation levels of a single method (RL), and 6.4%–23.0% across methods at their best observed optimisation level (optimised prompting vs transcript editing). All attacks were developed against proxy monitors only and transfer to the held-out GPT-5.4 target monitor. Conclusion: monitor-evasion evaluations can easily mislead — a basic-method evaluation gives false confidence that a monitor is strong.
Source: https://arxiv.org/abs/2611.34934

**2611.34188** MINE: A Training-Free Defense against Indirect Prompt Injection via Mutual Information and Embedding Variance — Existing RAG defences are reactive: prompt-engineering methods get overridden by injected instructions, supervised detectors need retraining per attack style. MINE flips the paradigm — **defend by maximising relevance, not by detecting attacks** — training-free, attack-agnostic, and doubling as a query-conditioned reranker. Introduces **LC-Inj-SQuAD**, a long-context benchmark averaging 4,032 words per context. Across four datasets (Inj-SQuAD, Inj-TriviaQA, LC-Inj-SQuAD, InjecAgent agent tool-call injection) MINE achieves the best accuracy–security trade-off among training-free defences and is the only one that stays usable against a fully adaptive attacker.
Source: https://arxiv.org/abs/2611.34188

**2611.34762** TASK Memory: Beyond Text-Only Memory with Activation Steering and Knowledge Editing against Memory Hallucination — Agents hallucinate about what they remember: the right memory is retrieved and placed in the prompt, but the answer contradicts it or the memory is applied to the wrong question. These are **use-time memory hallucinations**, arising from conflict between parametric knowledge and external memory, in three forms across five open models: **memory-ignoring** (returns to a stale fact in its weights, up to **46% of queries**), **memory-misapplying** (attributes the memory to unrelated entities, up to **24%**, and **49%** when retrieval is combined with weight editing) and **version confusion** (**53%** of answers about revised facts assert the superseded value when both versions remain stored). TASK memory combines a Text note with Activation Steering and Knowledge editing sharing one in-model address.
Source: https://arxiv.org/abs/2611.34762

**2611.34624** HoMe: Toward Practical Harness Optimization of Memory Systems for AI Assistants — The behaviour of long-running assistant memory systems is governed by the **harness** (code, prompts, configuration for memory construction, maintenance, retrieval and answer generation), and optimising it is largely manual; unrestricted editing alone does not ensure structural improvement. HoMe is evaluation-driven: it iteratively evaluates candidate harnesses, each new candidate derived from a previously evaluated harness by editing any part of it, and combines session-level memory versioning with execution traces to identify **shared failure mechanisms across cases** and localise them to the responsible sessions and harness components. Candidate gating encourages early structural exploration; smoke tests, adaptive sampling and memory reuse reduce evaluation cost. Validated with the open-source ReMe on LongMemEval-S and BEAM.
Source: https://arxiv.org/abs/2611.34624

**2611.33124** SAG-Mem-1.0 Technical Report — Long-term conversational memory must retrieve complementary facts scattered across sessions, including intermediate evidence with low similarity to the question. SAG-Mem preserves **complete dialogue messages in non-overlapping chunks** and discovers complementary evidence through **query-time lexical expansion**, avoiding derived memory representations or persistent relational structures that cost construction time and can lose source detail. Memory construction requires **no model inference** — a lexical index without LLM-based extraction, summarisation or semantic relation construction. At query time BM25 retrieves candidates, an evidence evaluator identifies useful chunks, and lexical cues from selected evidence drive a second retrieval round; retrieved dialogue is annotated with calendar interpretations of relative-time expressions.
Source: https://arxiv.org/abs/2611.33124

**2611.34635** ZeroHero: Training Small Language Agents from Scratch — Asks how much model capacity a specialised language agent actually needs. In each environment a large LM acts as expert and its successful trajectories are collected; each **SLA (fewer than 50M parameters)** is pretrained to predict the expert's responses given interaction history, then post-trained with PPO on its own interactions, where **reasoning alignment** supplements environment rewards with expert supervision on the language generated alongside actions. Evaluated in three multistep environments requiring both understanding and generating language (Crafter, WebShop, and one more).
Source: https://arxiv.org/abs/2611.34635

**2611.33639** How Much Effort Does an AI Code Reviewer Need? — Evidence from Claude 5.5 models on plausible-but-wrong patches (patches that pass a benchmark's tests but fail stronger ones). Claude Opus 5.5 (preregistered), Sonnet 5.5 and Haiku 5.5 (exploratory) each reviewed the same **90 agent-written Django patches from SWE-bench Verified** at low, medium and high effort. By strengthened SWE-ABS tests, **55 patches were wrong and 35 correct**. In every model, high effort accepted fewer wrong patches than low — false success **.45 vs .67 (Opus), .49 vs .65 (Sonnet), .51 vs .78 (Haiku)**; supported differences for Opus and Haiku. For Opus, medium was non-inferior to high within 15 pp (difference .018, 95% CI [−.065, .108]) and cost **20% less**, short of the preregistered 30%; for Sonnet and Haiku, medium cost 39% and 51% less than high.
Source: https://arxiv.org/abs/2611.33639
