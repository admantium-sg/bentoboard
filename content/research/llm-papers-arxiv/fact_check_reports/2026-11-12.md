## Trend Analysis

- **ArXiv paper claims remain the most reliable class in this corpus.** 15/15 exact matches, every ID resolving to the stated paper — no ID mislabeling (unlike the BitsMoE case of 2026-06-25), and no number drift. Every figure checked (percentages, speedups, sample sizes, p-values, N_c formulas, corpus counts) was present verbatim in the abstract or paper body.
- **The failure mode was operational, not epistemic.** The only real problem in this window was a crashed/unpersisted run on 2026-11-05 that silently dropped 10 completed verifications. The fix adopted here: a subagent must write its result file to disk, and the main agent must persist `verification_status.json` after every batch, so a partial run never repeats work.
- **Verification throughput is now the binding constraint, not source quality.** With 543 open units and a 15-claim cap, the 2026-10-30 → 2026-11-12 material (499 units, the bulk of it) will not be reachable for many runs. Raising MAX_CLAIMS or running 2 subagents × 2 batches per invocation is the only way to keep up with the daily accumulator.
- **Reuse of orphaned batch files is safe here** because the evidence in those files was already two-source; re-verification would have cost ~30 searches for zero new information. The trade-off: those facts carry a 2026-11-12 verified_date even though the evidence is from 2026-11-05 — acceptable for stable arXiv abstracts, but the `verified_date` should not be read as "fetched today".
