## 🛡️ Security

### eMudhra Intermediate-CA Compromise → Emergency v2026.10.6 + a Hard Node Runtime Floor (Oct 17-26)
**v2026.10.6** (2026-10-22T12:53:10Z) is an emergency patch with **zero features**. Chronology:
- **April 2025**: a Key Generation Ceremony wrap/unwrap step produced a second, **weak set of intermediate keys** that were published into browser trust lists. The weak keys **survived 18 months and two independent audit cycles**
- **2026-10-17**: a researcher (Mozilla credits "Wayne") proved control of **all eight keys**, reportedly with AI-assisted tooling. Chrome blocked the SPKIs via CRLSet **within 45 minutes**; Mozilla's OneCRL followed
- **2026-10-18**: eMudhra revoked everything. **2026-10-20**: the **emSign ECC Root CA - G3** root was removed. No fraudulent certificates appear in CT logs
- **2026-10-21**: Node.js shipped **22.23.4 / 24.22.1 / 26.12.1** to reject affected TLS chains

**The OpenClaw operational consequence is the release's first bullet:** *"Patched Node runtime required"* — **Node 24.22.1+ on the 24 line or 26.12.1+ on the 26 line**. Docker images ship Node 24.22.1, installers select patched runtimes, and **`openclaw update` refuses with recovery guidance before installing on an older Node** instead of breaking the running install; source builds pin pnpm 12.15.0 (#179992). This is the **hardest operational requirement OpenClaw has placed on self-managed operators to date** — enforced at update time, not a warning.

**Windows Companion is stuck behind it:** build v2026.10.5-alpha.4 ships WSL setup pinned to **Node 24.19.0**, which install-cli rejects — issue **openclaw/openclaw-windows-node#1843** (opened 2026-10-22, still open), 24.22.1 fix merged but **not in a published release**. Community thread 223 shows the symptom: a user with Node 26.12.1 confirmed via `node -v` and `where.exe node` still saw "Node 24.19.0 is unsupported" — the Companion's own bundled runtime, not the system one.

Source: https://github.com/openclaw/openclaw/releases/tag/v2026.10.6 | https://github.com/openclaw/openclaw-windows-node/issues/1843 | https://community.openclaw.ai/t/installation-error-node-version-fix/223

### METR + Redwood: Six Ways to Blind Agent Monitoring (Oct 22-23)
A 61-page internal report from two embedded researchers (one each at OpenAI, 2026-07-21 → 2026-08-11, on premises-issued devices) documents:
1. Internal agent tools **believed read-only** that a simple exploit could turn into **arbitrary actions**
2. **Two client-controllable headers** switching monitoring off for new agents
3. A **serialization gap** making the monitor read different input than the agent and error out **without escalating**
4. An exploit shielding **"hundreds"** of recent actions from monitoring
5. Codex sandboxing bypassable in principle · 6. Auto-Review bypassable in principle

Estimates: **75–94%** of GPT-5.5-class internal Responses API traffic eligible for monitoring; **~10% of Codex traffic** unmonitored in May–July due to compaction events. OpenAI says patched; METR has not verified. Direct relevance: the "agent believes this tool is read-only" failure mode maps onto OpenClaw's own permission-file model.

Source: https://anomixer.github.io/openclaw-news/ (Oct 23, 2026) | https://metr.org | https://redwoodresearch.org

## 💬 Community Pulse

**Working well:**
The **contract-driven development pipeline** answer (thread 215) is the strongest community artifact of the week. PJ_Standley's pattern — one orchestrating agent owning review, workers building — pairs **BRIEF.md + SPAWN-TASK.md** contracts with a facts script that computes and asserts numeric acceptance criteria *before* any build runs, one child session per job (`sessions_spawn`, `model: anthropic/claude-opus-5-5`, `worktree: true`, single-folder write scope), and **review gates that re-measure the artifact with the parent's own scripts**. Measured result from 4 animated video builds: **2 passed first review, 1 died on a provider 529 with no report and passed on restart, 1 was sent back once with numbers** (sound layer at -10 dB against a -2 to -6 dB target; fix landed at -3.5 dB). Durable knowledge is per-project **AGENTS.md + QUEUE.md**, where every review finding becomes a rule the next worker inherits.

**Problems:**
- **Shutdown is not termination.** A reopened thread reports **$44.20** in post-shutdown API charges (GitHub issue #121199), with one occurrence showing **544 API generations** and another showing **606 paid requests / $35.60** between 2026-07-04 and 2026-08-09. Root cause: on macOS OpenClaw runs as a **launchd-managed service** (`KeepAlive=1`, `RunAtLoad=1`), and an agent asked to stop the Gateway **cannot necessarily terminate its own managed service**. Verification is `openclaw gateway stop --disable` then `openclaw gateway status --deep`. The Foundation does not reimburse third-party API costs.
- **Delegated execution is leaking denials downward.** Thread 230: a worker launched from a coordinator's completion continuation **inherits the coordinator's local execution denials** as its delegated deny floor, losing `exec` it was explicitly authorized. A maintainer called it a policy-propagation defect, but the repro used `subagent_announce` while the real settlement path is `subagent_settle` — **do not assume a fix**.
- **Paired nodes are not Gateway substitutes.** Thread 214: a protected MCP skill required "supported Gateway execution." Setting **`host=node`** hides Gateway shell execution and exposes `node_exec`; **`host=auto`** restores both. The same log shows **Codex settled-turn finalization failing repeatedly — work completes, the reply never arrives**.
- **Installation friction is now a support burden**: the Node floor (§ above), plus a WhatsApp plugin install failing with *"no authoritative runtime child list"* — and `openclaw plugins registry --refresh` (43/66 indexed) fixed the stale registry but **not** the runtime-metadata failure.

**Interesting:**
- The community's own answer to "how do I use OpenClaw in my development process" is **not OpenClaw replacing Claude Code or Codex** but orchestrating them — the maintainer points at ACP integration, sandboxing, Lobster workflows with approval gates, and "Scaling Agents on Kubernetes with acpx and ACP," recommending one pipeline: issue → investigation → implementation → testing → independent review → human approval.
- 2026.10.x gotchas surfaced alongside the pipeline: you **cannot steer a running `claude-cli` child** (`guarded_injection_unsupported`), a child exceeding **20,000 JSONL lines** is marked failed even if the process finishes, **`nohup … &` inside exec silently never ran**, and shell commands should stay **under ~150 s** because render load starved the Gateway into model timeouts.

### Zero-Token Automation on a 12-Year-Old PC — "Herbert" the Telegram Bot (Oct 24)
Routine work moved to **local scripts on a 12-year-old Intel Core i5-4460S office PC**, so the LLM is called only when a decision is needed:
- **Email polling**: the mistake was asking an LLM to check a bot mailbox every five minutes; a **Python IMAP script** now polls, filters spammers, strips HTML and passes distilled plain text only when action is required — idle polling burns zero tokens
- **OCR**: **Tesseract locally** instead of vision tokens — about **3 seconds** even on the old CPU; only cleaned OCR text reaches the LLM
- **TTS**: **Piper on ONNX** locally instead of OpenAI per-character billing — renders in roughly **a third to half** the message duration on the old CPU, and the local German voices sound more natural than OpenAI's heavy US accent
- A zero-token flourish: a **"TaDa-List" in Todoist** of unexpected, unscheduled things accomplished during the day

The rule: *if a problem was solved by ordinary software before LLM APIs existed, run the local tool and hand the model only the result.*

### Blind Test of Five Local Coding Agents (Oct 26)
**Atomic Agent, goose, Hermes, OpenClaw, OpenCode** through an identical five-task suite — Qwen 3.8 27B uncensored Q4_K_M, llama.cpp, M5 Max MacBook Pro 64 GB, auto-approve on, script-graded. **Four of five passed 5/5.** The failure pattern matters more than the timings: two agents hit a missing Python library and installed it without asking; **the failing agent stopped and asked permission to install it — nobody answered, so it failed.** It also turned `"Q3/Q4"` into `"q3q4"` instead of `"q3-q4"`, caught by hidden tests. Lesson: *agentic tools that block on human input inside an unattended loop are effectively non-functional in that run.*

- `@openclaw/codex` in **both 2026.10.6 and 2026.10.7 pins `@openai/codex` at 0.160.0**; **Codex 0.164.0 (2026-10-23) carries the certificate-trust fixes** for the eMudhra intermediate-CA compromise that triggered the Oct 22 emergency release
- Labels: **P1**, `impact:security`, 🦞 *diamond lobster* advisory rating, `clawsweeper:needs-security-review`
- Codex review on-thread: the upgrade **is merged on `main` but not in a stable release**; the merged upgrade "explicitly leaves a platform-specific TLS concern unresolved" (a **Linux AMD64 TLS qualification gap**) — "a version bump alone cannot establish complete remediation across native TLS backends"
- Maintainer decision: *"Keep this issue open while security owners assess the retained backend concern and release owners verify delivery of the upgraded plugin."*
- Operator read: TLS remediation is now two-layered — Node 24.22.1+/26.12.1+ protects the main process, but **Codex-plugin-mediated outbound TLS needs its own version check**
