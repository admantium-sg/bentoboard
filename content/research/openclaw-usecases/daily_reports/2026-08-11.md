# Daily Report — 2026-08-11

## New Findings

### Platform — OpenClaw ExtendedStable Formalized as "Today's Top Story" (Aug 11)

The Claw Report's Aug 11 edition leads with OpenClaw formalizing its long-lived ExtendedStable release track. The new channel emphasizes predictable cadences, stricter change control, and backported critical and security fixes, alongside a compatibility matrix to keep plugins and extensions stable. This is positioned as the maturation milestone — OpenClaw is moving from "releases whenever" to a structured LTS-style track alongside weekly stable and beta channels.

### Platform — OpenClaw Academy: 2026.6.34 Extended-Stable Is the Upgrade to Take (Aug 8/11 coverage)

OpenClaw Academy published an independent operator analysis recommending upgrade to 2026.6.34 on the extended-stable channel. Key details:

- 25 audited pull requests on top of 2026.6.33, concentrating security-boundary, delivery-recovery and runtime-state repairs for unattended Gateways
- Browser, sandbox and network routes reject more unsafe access paths
- Agent and provider failures are less likely to silently end active work
- Channel recovery preserves pending work and bounded behaviour under retry or overload
- Status and diagnostic surfaces redact credential-bearing account details
- SQLite, workspace, process and plugin-response paths tolerate transient host conditions more safely
- Production dependency resolutions include patched versions of brace-expansion, PostCSS, fast-uri, ip-address and Undici

Operator recommendation: upgrade extended-stable to 2026.6.34 after a normal backup and canary. Pin exact version or digest for reproducibility rather than relying indefinitely on the moving channel alias. Community note: "The .34 release reduces both direct exposure and the operationally nastier class of failure where a run appears to finish but accepted work or context has quietly vanished."

Also: Plugin SDK removals are imminent — before_agent_start, root openclaw/plugin-sdk imports, providerAuthEnvVars, and channelEnvVars are scheduled for removal. Plugin maintainers must migrate to modern hook stages and focused SDK subpath imports.
<!-- Sources: https://openclaw.academy/blog/openclaw-2026-6-34-extended-stable-upgrade-decision/ -->

### Security — GitLab Advisory Database Cleans Up OpenClaw npm Advisories (Aug 11)

The GitLab Advisory Database (GLAD) page for the npm "openclaw" package now shows multiple OpenClaw advisories marked as duplicates and withdrawn, pointing operators to canonical GitHub Security Advisories (GHSAs) for definitive status. This is administrative cleanup — not new vulnerabilities. Operators should track original GHSAs rather than the npm-advisory duplicates.

## Community Pulse

**Working well:** Extended-stable as a formal LTS track — the community response on r/openclaw to the ExtendedStable announcement was positive: operators finally have a predictable, lower-churn upgrade path for critical workloads. The 2026.6.34 analysis from OpenClaw Academy giving explicit upgrade guidance (pin exact versions, run canaries, verify channel recovery) is described as exactly the kind of production-grade documentation operators need.

**Problems:** Plugin SDK deprecation warnings in 2026.6.34 are real and overdue — plugin authors who haven't migrated away from before_agent_start, root openclaw/plugin-sdk imports, and channelEnvVars need to act now. One community member noted: "extended-stable can preserve a runtime line; it cannot preserve deprecated third-party plugin contracts forever."

**Interesting:** The GitLab Advisory Database cleanup of duplicate/withdrawn npm advisories — while not new vulnerabilities, it signals that the vulnerability tracking ecosystem is consolidating around GitHub Security Advisories as the canonical source, which improves operator clarity.

## Trend

OpenClaw's maturation into a LTS-grade platform continues — the formalization of ExtendedStable with explicit upgrade guidance and the 25-PR security/reliability concentrate in 2026.6.34 signal a project increasingly targeting production unattended deployments rather than experimental use.
