### Security — Three new `impact:security` issues: provenance laundering, a removed-account tool-policy reset, and an owner-only collision
#187237 (P2) is the sharpest: the client-side compaction serializer uses unescaped in-band role labels (`[User]:`, `[Assistant]:`, `[Tool result of <tool>]:`) and "does not escape or neutralize the same label patterns when they appear inside message content." The consequence — "content the model merely read through a tool (a web page, a README, a PDF, an email body) can emit a line that is byte-identical to a genuine user turn inside the summarizer input" — targets the approval boundary, where a summary-level "the user already approved X" re-primes approval-escalation reasoning. #187513 (P1) is a policy regression: after a named Telegram account is removed while a routing binding still names it, "capped automations created from that account keep running under the channel's base group tool policy instead of failing before model/tool execution… Tools that were denied on the removed account become available again, up to the automation's cap." #187264 (P2) documents the owner-only scheduling collision, reported as a product decision rather than a bypass.

### Platform — Claude-CLI agents lose all history on a tool-list change
#186684 (P1): since 2026.10.7, `resolveCliSessionReuse` returns `{ mode: "invalidate", invalidatedReason: "prompt-tools" }` when the prompt-tool hash changes; under subscription auth the history reseed is then refused, so "The agent continues with `historyPrompt=none`, i.e. total amnesia." Because tool sets differ by trigger (user 44 / heartbeat 41 / event 40), "this fires routinely." Environment: Windows 11, 2026.10.8, 5 agents, largest agent DB 966 MB, Claude subscription auth.

## Community Pulse

**Working well:** An OpenClaw deployment was presented internally at a company and the blocker was documentation, not the product — the employee got "They love it" and then had no tutorial to implement it. The showcase's most-liked entry is a narrated end-to-end production change (Railway build diagnosis → config change → redeploy → PR over voice), and the vendor-template catalogues independently converge on one design rule: every template keeps a human in the approval loop on the irreversible step.

**Problems:** The ClawHub publication gate strands a real publisher with no recourse — "Security check: could not complete" is enough to hide a release while the owner CLI reports "Moderate CLEAN." The multi-user/team feature set is documented feature-by-feature but not as a use case, and the community's word for it ("multiplayer") appears nowhere in the docs. Recurring theme across three separate threads: state duplicated across surfaces (Lobsterdex vs Control UI, Workboard card lifecycle, cross-agent visibility in #106).

**Interesting:** OpenClaw has become the worked example that other platforms cite when discussing their own vendor lock-in — "There's a fear among third-party Claude tool-builders that Ant will close the shop very soon … Like they did with OpenClaw." In the same window it also shows up as a pejorative for sloppy agent output, inside an HN thread about anti-LLM obfuscation where a sibling commenter reports GLM-5.3 complying with a prompt frontier models refused.
