## New Multi-Agent Patterns (3)

### 1. SWAT (Markdown-Driven Squad Orchestration)
- **Source**: GitHub Discussion #41068
- **Manifest-driven**: MANIFEST.md defines squads
- **Task state**: OPERATION.md tracks tasks
- **Accumulated learnings**: INTEL.md stores insights
- **Pure prompt engineering**: No custom code required
- **Best for**: Produce, evaluate, iterate workflows

### 2. OpenMOSS (Self-Organizing Multi-Agent)
- **Source**: GitHub (uluckyXH/OpenMOSS)
- **Autonomous**: Agents plan, execute, review, patrol with zero human intervention
- **More autonomous** than SWAT
- **Best for**: Workflows requiring full autonomy

### 3. Lobster Dev Pipeline (Deterministic Code-Review-Test)
- **Source**: DEV Community article
- **3 agents**: Programmer (Opus), Reviewer (Sonnet), Tester
- **Sequence**: Code → Review (max 3 iterations) → Test → Done
- **Deterministic YAML**: Lobster controls workflow transitions, not LLMs
- **Principle**: Agents do writing/analysis (what LLMs excel at); Lobster does sequencing/retrying (what code excels at)

## Multi-Agent Orchestration Deep Dives

### Heyuan110.com Guide Highlights

**Key Insight**: "Stop letting LLMs handle orchestration"

**Single-Agent Ceiling Problems**:
1. **Memory pollution**: Irrelevant context retrieval, degraded precision >200MB
2. **Persona confusion**: One SOUL.md cannot handle multiple contradictory personas
3. **Model mismatch**: One model for everything = overpaying or underperforming

**Solution: Multi-Agent Architecture**
- Separate workspace, memory, persona, model per agent
- **Cost optimization**: Haiku supervisor + Sonnet specialists = 40-60% cheaper
- **8-tier binding priority**: Exact peer → Parent peer → Discord roles → Guild ID → Team ID → Account ID → Channel default → Fallback

**Tool Isolation by Role**:
- Researcher: web_search, browser automation
- Drafter: read, write, edit
- QC Agent: validators, quality checkers
- Technical Finisher: publish automation

### OpenClawMCP.com Pattern Comparison

**Three Distinct Patterns**:

1. **Sub-agents**: Background workers spawned from main agent
   - Non-blocking: Returns run ID immediately
   - Configuration: maxSpawnDepth (1-5), maxConcurrent, maxChildrenPerAgent
   - Best for: Long-running research, batch processing, code review

2. **Multi-agent routing**: Separate independent agents on one Gateway
   - Fully isolated: Separate workspace, auth profiles, session store
   - Per-agent sandbox modes and tool restrictions
   - Best for: Home/work separation, security isolation, different personas

3. **Agent teams**: Community-built orchestration systems
   - SWAT, OpenMOSS, Mission Control
   - Add structured coordination layer
   - Best for: Complex pipelines, review loops, 24/7 operations

**MCP Tool Isolation**:
- Gateway-level configuration in openclaw.json
- Per-agent tool allow/deny lists
- Sub-agents inherit parent MCP tools unless restricted
- Example: Researcher gets Brave/Firecrawl; Coder gets GitHub/Desktop Commander
