### Security — "Phantom Context": Unit 42 Discloses Long-Term Memory Injection Flaw; OpenClaw Spared (Aug 22)

Unit 42 disclosed "Phantom Context" on Aug 22 — a new attack chain where malicious instructions planted in an agent's persistent memory store auto-replay on the next session, bypassing the runtime sandbox. Three mainstream cloud coding agents were hit in testing; none isolated memory from runtime permissions. OpenClaw was explicitly spared because its architecture requires each agent's memory to live inside the boundary defined by the permission file and pass the gate before replay. Edge Farmer: "When 'memory' becomes the new attack surface, the unit of containment upgrades from 'sandbox' to 'who is allowed to let the agent remember what'; the lobster's answer never changed — memory and execution both run inside the permission file you can actually read."
Source: anomixer.github.io/openclaw-news (Aug 22), Unit 42 Palo Alto Networks (Aug 22)

### Standards — Agentic AI Foundation Makes "Permission File" a First-Class MCP Concept (Aug 22)

The Agentic AI Foundation released MCP spec revision 2026.8 on Aug 22 — for the first time writing "permission file" as a first-class abstraction: agents must consult an auditable local authorization list before replaying memory, calling tools, or communicating with other agents. Seen as a direct institutional response to Phantom Context and Anthropic's multi-agent "turf war" study. Edge Farmer: "When a neutral foundation writes 'permission file' into the standard, it admits the unit of containment in the multi-agent era is permission design, not a bigger sandbox; the lobster has always run this way."
Source: anomixer.github.io/openclaw-news (Aug 22), Agentic AI Foundation MCP spec 2026.8
