**1. NEW SECURITY ADVISORY — GHSA-pw3x-g8v8-fvj2, HIGH, CVSS 8.8, published 2026-11-19T02:01:59Z.**
"OpenClaw delegation could skip approval for restricted agents." CWE-863 (Incorrect Authorization), vector `AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H`, reporter `doctoroakin`. The `openclaw` tool could apply **persistent configuration changes without approval** when tool policy denied execution and file writes — letting a restricted agent **enable host command execution through configuration changes**. Patched versions: **first stable `2026.11.4`**, extended-stable **`2026.10.33`**. The advisory explicitly does not change OpenClaw's trusted-operator model (authenticated Gateway operators, installed plugins and intentional local execution surfaces stay trusted unless a separate policy/approval/allowlist/sandbox/auth boundary is crossed). Mitigation: upgrade; before upgrading set `tools.exec.mode` to `ask` and deny untrusted delegated changes; keep channel/tool allowlists narrow; do not share one Gateway between mutually untrusted users.
Source: https://api.github.com/repos/openclaw/openclaw/security-advisories/GHSA-pw3x-g8v8-fvj2

## Community Pulse

**Working well:**
- The **completion-handoff pattern** is genuinely desired: in #482 the visible specialist produced a reviewed plan, answered the user's two questions in its own chat, and finished — only the return trip to the lead broke.
- **Forum discovery works as a top of funnel**: the single documented stranger→signup→shipped-artifact conversion in the window came from the OpenClaw community forum, zero-touch, while the founder was asleep.
- **Release channel breadth**: stable + extended-stable shipped within a day, and an independent verifier published downgrade guidance within hours of the release.
- Clawstat's read of sentiment is fair: "quiet rather than angry… 60 tracked issues drew only 1 👍 against ~3.1M weekly npm downloads… the complaints come from specific configurations rather than broad backlash."

**Problems:**
- The **upgrade path**, not the runtime: unattended auto-update leaving the Gateway stopped, a dead Gateway lock rolling back the 2026.11.5 update, Windows Defender hanging the node, `curl | bash` onboarding broken — and **no supported read-only diagnostic** to distinguish a slow `openclaw doctor` from a stalled one (still running after 37 h 40 m).
- **Multi-agent completion is the recurring weak link**: #451 (visible delegation), #475 (dispatch-and-return), #482 (handoff failure) — three days, three threads.
- **Configuration granularity is a real gap**: per-specialist tool/system-prompt scoping cannot be done via `openclaw.json` today.
- **Supply without adoption** is now the dominant ClawHub pattern (86 skills → 5 installs, 0 stars, 64% of publishers shipping exactly one skill).

**Interesting:**
- The advisory + backport + catalog-outage chain shows a **release-engineering change reaching users as degraded model availability** rather than as a security fix — the opposite of the intent.
- The community is **starting to police its own claims**: `mechanism-value-verdict`, `claim-audit`, `evidence-anchor`, `skill-improver` and `kitbay`'s fact-check gate suggest the low-adoption phase is read as a trust problem, not only a demand problem.
- **Version guidance is contested**: clawstat recommends staying on 2026.11.3 while joe tells users to update to latest stable — two channels, two answers, same week.

## Trend
A release-channel change made for security (extended-stable backport) caused a 33-hour hosted model-catalog outage that was fixed in-window, while the same backport turned out to be the patch for a newly published CVSS 8.8 delegation-approval advisory — and the independent verifier responded to both by keeping its recommended version one minor release back. Overall: security response is now sharp, but the release pipeline it depends on is fragile, the tracker is being flooded by automated triage, and the multi-agent completion handoff remains the single most-requested and least-reliable capability.
