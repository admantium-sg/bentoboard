### 5. Platform — Performance regressions quantified: a full SQLite integrity check per shared-state opener, and O(n²) re-parsing of streamed replies
#186631 (P1, `impact:crash-loop`) — `assertOpenClawStateRuntimeIntegrity` falls back to a full `PRAGMA integrity_check` + `foreign_key_check` whenever there is no borrowed host proof, so **every CLI process and every fresh Gateway worker thread pays a whole-file scan**. Measured over 24 h on 2026-10-27: **345 admissions ≥1 s totalling 5,089 s** (Gateway workers 205 / 3,520 s; CLI processes 140 / 1,570 s), max **184.5 s**; **84 of 141** main-thread `slow agent database reservation` events ≥10 s (2,039 s) coincided with it. #186621 — a streamed reply carrying a `MEDIA:` attachment line never reaches the append fast path, so the whole accumulated answer is re-parsed on every provider delta: **10.5 s of blocked Gateway main thread at 64 KB and 25.4 s at 128 KB**; plain prose too (128 KB re-parses 906.9 M characters, 7.5 s block). Both land directly on the release whose own headline claims *"long HTML and JSX answers … no longer stall the Gateway"*.
Source: https://github.com/openclaw/openclaw/issues/186631 | https://github.com/openclaw/openclaw/issues/186621

### 6. Platform — Only 111 of 229 installed skills reach the system prompt, names only
#186607 measures the injected `<available_skills>` block and finds it carries names only — the block itself warns *"Skills truncated: included 111 of 229 (compact format, descriptions omitted)"*. Skill selection quality depends on descriptions, so agents must call `skills_search` blindly or guess from names, causing under- or mis-selection in every session including subagents and cron jobs that cannot carry extra context files. Requested fix: inject each skill's frontmatter `description` (truncated to ~80 chars) with a configurable catalog size budget — flagged as a prompt-injection surface.
Source: https://github.com/openclaw/openclaw/issues/186607

### 10. Use case — The cost-of-ownership floor: agents 24/7 on two $26/month VPSes, with a hand-rolled credit governor
A developer runs multiple agents 24/7 on **two Hostinger KVM 8 boxes (8 vCPU, 32 GB RAM, 400 GB NVMe) at $25.99/month** on a 24-month US commit renewing at **$49.99** — across 54 locales the same plan ran $22–$32/month, and local currency with a 20% referral discount brought his to **~$18**. The constraint: *"a KVM 8 can burst to all 8 cores while credits last, but earns credits back at only 4.8 cores' worth. Once the balance hits zero, the whole box drops to 30% (2.4 cores)"* — Hostinger limited his box **13 times in 10 days**, capping every service on it. The open-sourced fix budgets the credit pool so load eases to the 4.8-core baseline. The architecture is the interesting part: **an Ansible repo rebuilds the box from an empty VM in ~two hours**, the server applies each change to itself after checks pass, **no open ports** (everything dials out, Tailscale for access), **each agent or service runs as its own Linux user** so they cannot read each other's files, agents report to a private Telegram group with one topic per project, **five actions always wait for a tap** (spending money, deleting production data, security changes, messaging all users at once, sending personal data somewhere new), `/freeze` stops every agent at once, and **no agent holds an API key** — keys live in small broker services that validate each request, act, and keep an undo record. Reason for VPS over laptop: *"A sleeping laptop can't run scheduled agents"*. Cost context: Hetzner raised its 8-core/32 GB server from €62.49 to **€138.49/month** in June.
Source: https://openclawradar.com/article/hostinger-governor-ai-agents-247-vps-cpu-credits

### 11. Use case / ROI — 14,000 calls: humans convert ~4x better, AI hangs up 7x more without progress
Bold Agent Kit compared **~14,000 inbound calls (6,343 AI-handled, ~7,657 human-handled)**. **Human receptionists delivered ~4x stronger inbound intake conversion**; **AI-handled calls had 700% more no-progress hangups**. Cause was not isolated — conversational friction, response delays, unexpected questions, caller preference — and humans **missed ~15% more calls**. The builder-relevant framing: *"AI's real advantage is availability… But answering more calls isn't the same as producing more business — an automated system that answers everything but can't convert may not deliver the expected ROI."* Recommended shift: measure **intake conversion and abandoned-without-progress rate**, not call-answer rate. Backdrop: a16z (Oct 9) using Revelio employment data finds **global call-center employment growth turning negative across income groups** — the first sustained decline after more than a decade of expansion.
Source: https://openclawradar.com/article/call-center-jobs-declining-14000-calls-humans-outperform-ai
