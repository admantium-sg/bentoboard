### Platform — OpenClaw Ships 2026.8.1.1 Hotfix: Permission-File Stamps in Memory Boundary; "Permission File as Code" on 2026.8.2 Roadmap (Aug 25)

OpenClaw shipped 2026.8.1.1 on Aug 25 — a hotfix resolving claw-perms false positives under high-concurrency scanning and embedding a "permission-file version stamp" into every agent's long-term memory boundary, forcing a cryptographic stamp check before any memory replay. If the stamp doesn't match the current permission file, the replay refuses to load. The team also added "permission file as code" to the 2026.8.2 roadmap — formal version-control and diff workflow for permission files themselves. Community: "When 'stable before update' evolves from a checklist into a postmark — every context you remember carries the seal of the gate it shipped through."
Sources: anomixer.github.io/openclaw-news (Aug 25), openclawai.io/changelog

### Security — Third Phantom Context Variant Registered as CVE-2026-54231: Retrieval-Based Context Poisoning; claw-perms Ships Same-Day (Aug 25)

Unit 42 registered Phantom Context's third variant as CVE-2026-54231 on Aug 25 — exploiting RAG retrieval pipelines rather than long-term memory writes. The attack poisons a document store so that when a RAG agent retrieves context, the poisoned document auto-replays in-session. Unlike CVE-2026-54210 (per-agent persistent memory) and CVE-2026-54229 (cross-agent shared memory), this attacks "where the agent fishes from." OpenClaw's claw-perms shipped retrieval-source-signature detection rules the same day. Community: "The unit of containment upgrades from 'what the agent remembers' to 'where the agent fishes what from'; every chunk of incoming context must clear the signature of your local gate."
Sources: anomixer.github.io/openclaw-news (Aug 25), NVD
