## Trend Analysis
- **Error pattern:** all three hard corrections are *derived/aggregated* values rather than raw API values — a novelty claim ("first"), a duration ("~9h") and a ratio ("64%"). Raw quoted values (timestamps, hashes, PR numbers, CVSS vectors, issue titles) were essentially error-free.
- **Second pattern:** partial-page API queries (GitHub search returns max 100 items) systematically undercounted label and P0 tallies. Both runs' tracker items should be re-worded as "first 100 of N" or re-queried with explicit pagination.
- **Third pattern:** live counters drift fast in this repository (≈+100 stars and +160 open issues per day); every counter claim must be attributed to its snapshot moment.
- **Source reliability:** official endpoints (npm registry, GitHub API/advisories, Discourse JSON, ClawHub API) were fully reliable. The only weak spot was ClawStat's missing 2026-11-18 raw capture, which forced a second-hand citation for the `wait` → `care` transition.
- **Reliability of the research pipeline:** the daily findings are strong on release/advisory/security detail and weaker on derived aggregates — the highest-value fix for the accumulator is to compute label/issue tallies with pagination and to avoid novelty superlatives.
