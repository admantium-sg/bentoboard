3. Publisher-concentration percentages are computed over the truncated 138-item window sample, not over all ClawHub output for the day.

5. The ClawStat assessment timestamp (2026-11-14T01:58Z) falls in-window, but it evaluates version 2026.11.3 — i.e. it is a re-reading of an unchanged release, not a response to anything published in the window.
6. `release/2026.11.4` branch pins (dompurify 3.4.16, npm 12.2.0, undici 8.12.2) are behind `main` (3.4.17 / 12.2.1 / 8.12.3); the release branch is expected to be cut fresh, so the vulnerable dompurify remains live for anyone installing from that branch.
7. The `#196925` advisory issue carries a `clawsweeper:no-new-fix-pr` label, so "no fix PR" for dompurify on the release branch is expected rather than evidence of a stalled fix.
8. Enterprise merged-PR counts include large mechanical TypeScript migrations; commit count being flat at 181 while merged PRs rose to 181 suggests a shift in commit granularity, not reduced activity.
