**Performance regressions surfaced in the 24h window — a full `PRAGMA integrity_check` on every shared-state opener, and O(n²) re-parsing of streamed attachments**
**#186631** (Oct 28 07:55 UTC, P1, `impact:crash-loop`, rated 🐚 platinum hermit) documents that `state.admission.fast-path` → `assertOpenClawStateRuntimeIntegrity` falls back to a full `integrity_check` + `foreign_key_check` whenever there is no borrowed host proof — so **every CLI process and every fresh Gateway worker thread pays a whole-file scan**. Measured over 24 h on 2026-10-27: **345 admissions ≥1 s totalling 5,089 s** (Gateway workers 205 / 3,520 s; CLI processes 140 / 1,570 s), max **184.5 s**; **84 of 141** main-thread `slow agent database reservation` events ≥10 s (2,039 s) coincided with it. Environment: agent DBs of 0.57–0.93 GB (WAL) on ext4 over a ZFS zvol throttled to 3,000 IOPS / 70 MB/s with page cache evicted. **#186621** (Oct 28 07:30 UTC, P2, linked PR open) shows that a streamed reply carrying a `MEDIA:` attachment line never reaches `createStreamingReplyResolver`'s append fast path, so the entire accumulated answer is re-parsed by `parseReplyDirectives` on every provider delta: **10.5 s of blocked Gateway main thread at 64 KB and 25.4 s at 128 KB** (~4× per doubling); plain prose is affected too — 128 KB re-parses 906.9 M characters and blocks for 7.5 s. Both land directly on the release whose own headline claims *"long HTML and JSX answers … no longer stall the Gateway"*.
Source: https://github.com/openclaw/openclaw/issues/186631 | https://github.com/openclaw/openclaw/issues/186621

**Feature request exposes a real capability gap: only 111 of 229 installed skills reach the system prompt, names only**
**#186607** (Oct 28 06:56 UTC, enhancement, P3) measures the injected `<available_skills>` block and finds it carries names only — the block itself warns *"Skills truncated: included 111 of 229 (compact format, descriptions omitted)"*. Because skill selection quality depends on descriptions, agents must call `skills_search` blindly or guess from names, causing under-selection or mis-selection in every session including subagents and cron jobs that cannot carry extra context files. The requested fix is to inject each skill's frontmatter `description` (truncated to ~80 chars) and make the injected catalog's size budget configurable. The issue also flags the *inverse* risk — injecting skill descriptions into the system prompt is a prompt-injection surface — which is why it asks for a configurable budget.
Source: https://github.com/openclaw/openclaw/issues/186607

**Background (Sept 29 announcement, not previously recorded in this knowledge base): OpenClaw Enterprise, and OpenAI running OpenClaw agents on its own code**
OCE is a free, MIT-licensed, vendor-neutral control plane for persistent agents, with multi-tenant administration, fine-grained permissions, workload isolation, sandboxing and auditing; companies can swap in their own models, harnesses and sandboxes. Provenance: the project *originated inside OpenAI* and was donated to the **OpenClaw Foundation**, developed with contributions from **Red Hat and Nvidia**; **OpenAI and Red Hat are already piloting it internally**. The most revealing detail for real-world deployment: OpenAI staff member **RJ Marsan** describes an internal agent called **Androidclaw** that operates across company context, Git, GitHub and logging systems — it investigates broken builds, identifies the relevant pull request, traces product problems back to incidents and in some cases **prepares and merges fixes**; Marsan called it *"well-adopted"* internally and its issue-tracing-to-fix-publish loop *"kinda game changing"*. OpenClaw's stated motivation is that some IT organizations have simply **banned** autonomous agent platforms for lack of governance controls, and OCE is the layer between "ban it" and "unchecked access".
Source: https://venturebeat.com/orchestration/openclaw-launches-free-enterprise-control-plane-for-persistent-ai-agents-backed-by-openai-red-hat-and-nvidia | https://openclaw.ai/blog/openclaw-enterprise/
